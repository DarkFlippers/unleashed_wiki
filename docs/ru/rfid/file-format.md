# Форматы файлов 125 кГц RFID

В `/ext/lfrfid/` лежат три вида файлов:

| Расширение | Что описывает | Кто создаёт |
|---|---|---|
| `.rfid` | **Карту**: протокол + ID | Read → Save, Add Manually |
| `.t5577` | **Чип**: все блоки T5577 | [Приложение T5577](/ru/rfid/t5577-app) |
| `.ask.raw` / `.ask134.raw` / `.psk.raw` | Запись «сырого» сигнала | [RAW](/ru/rfid/raw) |

## `.rfid` — ключ LF RFID

```text
Filetype: Flipper RFID key
Version: 1
Key type: EM4100
Data: 01 23 45 67 89
```

Файл хранит один ключ типа, указанного в `Key type`.

| Поле | Описание |
|---|---|
| `Key type` | Имя протокола, точно как в [таблице протоколов](/ru/rfid/protocols) |
| `Data` | Данные ключа в hex; длина фиксирована для каждого протокола |

Допустимые значения `Key type` в этой прошивке: `EM4100`, `EM4100/32`, `EM4100/16`, `Electra`, `H10301`, `Idteck`,
`Indala26`, `Indala224`, `IoProxXSF`, `AWID`, `FDX-A`, `FDX-B`, `HIDProx`, `HIDExt`, `Pyramid`, `Viking`,
`Jablotron`, `Paradox`, `PAC/Stanley`, `Keri`, `Gallagher`, `Nexwatch`, `Radio Key`, `GProxII`, `Noralsy`.

История версий: 1 — первая версия. Старые файлы с `Key type: I40134` (3 байта) при загрузке конвертируются в
`Indala26`.

::: tip
Ключ можно создать на компьютере: напишите четыре строки как выше с нужным `Key type` и правильным числом байт в
`Data`, скопируйте в `/ext/lfrfid/` — и он появится в **Saved**.
:::

## `.t5577` — дамп T5577

```text
Filetype: Flipper T5577 dump
Version: 1
# Block 0: ASK/Manchester, RF/64, 2 data blocks, password enabled
Page 0 blocks read: 0 1 2 7
Page 0 Block 0: 00 14 80 50
Page 0 Block 1: 12 34 56 78
Page 0 Block 2: 9A BC DE F0
Page 0 Block 3: 00 00 00 00
Page 0 Block 4: 00 00 00 00
Page 0 Block 5: 00 00 00 00
Page 0 Block 6: 00 00 00 00
Page 0 Block 7: 0C 0D 0E 0F
Page 1 blocks read: 0 1
Page 1 Block 0: E0 15 00 1A
Page 1 Block 1: 20 24 10 00
Page 1 Block 2: 00 00 00 00
Page 1 Block 3: 00 00 00 00
Password: 0C 0D 0E 0F
```

Файл `.t5577` описывает **кристалл**, а `.rfid` — **карту**. T5577, настроенную как EM4100, можно сохранить и так, и
так, но файлы не взаимозаменяемы: в `.t5577` есть конфигурация, определяющая, как чип «разговаривает», и пароль,
которым он защищён.

| Поле | Описание |
|---|---|
| `Page 0 blocks read` | Блоки страницы 0, значения которых реально прочитаны с чипа, через пробел |
| `Page 0 Block 0..7` | Содержимое блока, 4 байта hex, старший байт первым. Блок 0 — конфигурация, блок 7 — пароль |
| `Page 1 blocks read` | Прочитанные блоки страницы 1 |
| `Page 1 Block 0..3` | Блок 0 повторяет конфигурацию; 1–3 — заводские данные прослеживаемости |
| `Password` | Необязательное. Пароль, который **точно подходит** к чипу |

Главные правила:

- **У каждого блока есть ключ**, прочитан он или нет. Содержимым считаются только блоки из `blocks read`, остальное —
  заполнитель, его нельзя записывать на метку. Файл без единого прочитанного блока отвергается.
- Защищённый чип не отдаёт блок 0, нужный для определения, поэтому без пароля дампа нет вообще (а не частичный).
  Частичный дамп означает, что метка «уплыла» из поля.
- `Password` и `Page 0 Block 7` — разные факты и могут не совпадать: блок 7 — то, что в нём было при чтении (обычные
  данные, если пароль не включён), а `Password` — подтверждённый пароль. Снятие пароля сбрасывает только бит в блоке 0,
  в блоке 7 остаётся старое значение.
- Строка-комментарий с расшифровкой блока 0 — только для человека.

### Порядок восстановления

При записи дампа обратно (приложение T5577 → **Write to Tag**) порядок как в Proxmark3:

1. Страница 0, блоки 1–7. Начиная с блока 7 запись должна идти с паролем, который теперь лежит в блоке 7.
2. Страница 1, блоки 1–3 (блок 0 страницы 1 не пишется никогда). Оригинальные чипы не меняют блоки 1–2 — это
   сообщается как *unchanged*, а не как ошибка.
3. Блок 0 страницы 0 — **последним**: он меняет то, как чип отвечает.
4. Пишутся только блоки из `blocks read`.
5. Нулевой блок 0 **не пишется никогда**: чип с ним вообще ничего не отвечает, и пути назад нет.

На кадры записи метка не отвечает, поэтому успех можно узнать только обратным чтением блоков.

## `.raw` — RAW-записи

Двоичные файлы режима RAW. В начале — заголовок:

| Поле | Тип | Значение |
|---|---|---|
| magic | uint32 | `0x4C464952` |
| version | uint32 | `1` |
| frequency | float | частота несущей, Гц (125000 или 134200) |
| duty_cycle | float | скважность несущей |
| max_buffer_size | uint32 | размер наибольшего буфера в файле |

Далее идут буферы, каждый с префиксом-размером, с varint-кодированными парами *(импульс, длительность)*. Расшифровать
их можно командой CLI `rfid raw_analyze <filename>`.
