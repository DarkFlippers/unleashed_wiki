# Как помочь и переводить

Эта вики — сайт на [VitePress](https://vitepress.dev). Страницы — обычный Markdown, каждая страница существует на
**всех языках**, и каждая страница, использующая источник, его **указывает**.

## Как устроена вики

Контент лежит в `docs/`, разбитый по языку, затем по разделу:

```
docs/              # английский (корневая локаль)
  nfc/read.md
  community/credits.md
docs/ru/           # русский — точно повторяет docs/
  nfc/read.md
  community/credits.md
```

Правило простое: **каждая страница существует по одному и тому же пути на каждом языке.** Английская
`docs/nfc/read.md` и русская `docs/ru/nfc/read.md` — это одна страница на двух языках. Если страница есть на одном
языке, она должна быть на всех — запустите `npm run check`, чтобы увидеть недостающие.

Разделы (папки верхнего уровня) заданы в `docs/.vitepress/i18n/sections.ts`; у каждого раздела есть `index.md` —
его титульная страница.

## Frontmatter

Каждая страница начинается с YAML-блока frontmatter:

```yaml
---
title: Чтение карт              # подпись в сайдбаре + заголовок страницы
order: 20                       # порядок в сайдбаре раздела (10, 20, 30…)
author: gromovyna               # ТОЛЬКО если использован материал @gromovyna
original: [https://docs.flipper.net/zero/nfc/read, https://telegra.ph/...]
sources: [flipper-docs, unleashed-docs]
---
# Чтение карт
```

- **`title`** — показывается в сайдбаре и как заголовок.
- **`order`** — позиция в сайдбаре раздела. Используйте кратные 10, чтобы можно было вставлять страницы позже.
  Страницы `index.md` разделов — титульные и `order` не получают.
- **`author`** — ставьте `gromovyna` (единственный зарегистрированный ключ автора), когда использован **любой** его
  материал, даже частично. Рендерит выделенную карточку благодарности внизу.
- **`original`** — список **точных** URL, по которым построена страница. Обязателен, если источник использован.
- **`sources`** — ключи всех использованных источников (см. ниже). Обязателен на каждой контентной странице,
  включая `index.md` разделов.

Держите **одинаковый frontmatter на всех языках** — перевод страницы не меняет, кому она приписана.

## Благодарности обязательны

Если страница использует *любой* источник — статью, пост, документацию или код прошивки — его нужно указать. Блок
благодарностей внизу каждой страницы генерируется из frontmatter выше. Допустимые ключи источников заданы в
`docs/.vitepress/sources.ts`; текущие ключи:

| Ключ | Источник |
|---|---|
| `gromovyna` | статьи и канал @gromovyna |
| `how2flipper` | канал @how2flipper_rus |
| `flipper-docs` | docs.flipper.net |
| `unleashed-docs` | документация Unleashed |
| `unleashed-readme` | ReadMe Unleashed |
| `unleashed-src` | исходники прошивки Unleashed |
| `li0ard` | блог li0ard |

Построение страницы по исходникам прошивки — тоже использование источника: добавьте `unleashed-src` в `sources` и
нужную папку исходников на GitHub в `original`.

Как формировать URL в `original`:

- **Документация Flipper** — `https://docs.flipper.net/zero/<path>` (то есть `zero_nfc_read.md` → `/zero/nfc/read`).
- **Документация Unleashed** — `https://github.com/DarkFlippers/unleashed-firmware/blob/dev/documentation/<Файл>.md`
  (пробелы как `%20`).
- **ReadMe** — `https://github.com/DarkFlippers/unleashed-firmware/blob/dev/ReadMe.md`.
- **gromovyna** — URL статьи на `telegra.ph` и/или `https://t.me/gromovyna/<id>`.
- **how2flipper** — `https://t.me/how2flipper_rus/<id>`.

## Стиль

- Настоящий гайд, а не копия. Переписывайте своими словами, объединяйте пересекающиеся источники, перестраивайте под
  читателя.
- Ориентируйтесь **на Unleashed**: где Unleashed отличается от стока, пишите это в блоке `::: tip Unleashed`.
- Каждая страница функции: что это → когда применять → нумерованные шаги с точными путями меню
  (`Main Menu → Sub-GHz → Read`), кнопки как `<kbd>OK</kbd>`, ожидаемый результат, типичные ошибки, связанные ссылки.
- Сохраняйте технические факты точно: частоты, форматы файлов, пути вроде `/ext/subghz/`, команды CLI, названия
  протоколов, версии. Не выдумывайте функции — если не уверены, не пишите.
- Используйте контейнеры VitePress: `::: tip`, `::: warning`, `::: danger`, `::: details`. Из «сырого» HTML
  разрешён только `<kbd>`; никаких Vue-компонентов.
- Внутренние ссылки — абсолютные и без расширения: `/nfc/mfkey` в английском, `/ru/nfc/mfkey` в русском. Ссылайтесь
  только на существующие страницы.

## Как добавить страницу

1. Создайте `docs/<раздел>/<страница>.md` с frontmatter и контентом.
2. Создайте зеркало на **каждом** другом языке по тому же пути (например, `docs/ru/<раздел>/<страница>.md`).
3. Добавьте её в список в `index.md` раздела.
4. Запустите `npm run check`, чтобы убедиться, что ни на одном языке страница не пропущена, затем
   `npx vitepress build docs` — он ловит битые ссылки (они считаются ошибками сборки).

Сайдбар генерируется автоматически из файлов и их `order`, так что отдельный список править не нужно.

## Скриншоты экранов устройства

Экраны Флиппера из `/screens/…` **не сняты, а сгенерированы**. Команда `npm run screens` компилирует сам GUI-код
прошивки (canvas, `gui/modules/*` и view приложений) и рендерит каждый экран в
`docs/public/screens/<раздел>/<имя>.png`. Результат попиксельно совпадает со скриншотом из qFlipper: тот же кадр
128x64, те же два цвета, увеличение ×4. Рендерер лежит в `scripts/screens/` — в его `README.md` описаны требования,
откуда берётся чекаут прошивки и как формат вывода выведен из кода qFlipper.

Как добавить новый экран:

1. Напишите блок `SCREEN(...)` в `scripts/screens/specs/<раздел>.c`. Соберите view ровно так, как это делает сцена
   приложения (`submenu_add_item`, `widget_add_*`, `popup_set_*`, собственные сеттеры view), с правдоподобными
   данными-заглушками.
2. Запустите `npm run screens` (или `bash scripts/screens/build.sh --only <раздел>/` для одного раздела).
3. Сошлитесь на PNG со страницы: `![альт-текст](/screens/<раздел>/<имя>.png)`. Путь **одинаковый на всех языках**,
   переводится только альт-текст.

Ставьте скриншот рядом с тем шагом или экраном, который он иллюстрирует, а не галереей в начале страницы, и не
больше нескольких на страницу. В `docs/public/screens/manifest.json` перечислены все сгенерированные экраны с
названием, путём в меню и сценой прошивки, из которой взято состояние.

## Как добавить новый язык

Реестр языков — `docs/.vitepress/i18n/`. Чтобы добавить язык `xx`:

1. **Скопируйте строки.** Скопируйте `docs/.vitepress/i18n/en.ts` в `docs/.vitepress/i18n/xx.ts` и переведите все
   строки. Задайте `prefix: 'xx'` (станет префиксом URL `/xx/`).
2. **Зарегистрируйте.** В `docs/.vitepress/i18n/index.ts` импортируйте файл и добавьте его в массив `LOCALES`.
3. **Создайте страницы.** Создайте `docs/xx/`, зеркалящий `docs/` — те же имена и пути — и переведите каждую
   страницу. Держите frontmatter одинаковым (те же `author`, `original`, `sources`).
4. **Проверьте.** Запустите `npm run check`, чтобы увидеть недостающие на новом языке страницы, заполните пробелы,
   затем соберите.

::: tip Контент не требует правок `.vitepress/`
Всё выше, кроме *добавления языка*, — чистый Markdown в `docs/`. Сайдбар, навбар и блок благодарностей
генерируются — не трогайте `docs/.vitepress/`, если только вы не добавляете язык или ключ источника.
:::
