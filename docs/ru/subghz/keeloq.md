# KeeLoq

KeeLoq — шифр, на котором построено огромное количество пультов ворот, гаражей и шлагбаумов (DoorHan, Nice Smilo,
FAAC RC, BFT, Came Space, Beninca, Hormann EcoStar…) и старых автосигнализаций.

Теоретическая часть основана на статье **«KeeLoq и с чем его едят»** автора [@li0ard](https://blog.li0ard.rest/wtfiskeeloq)
из исследовательской команды @gromovyna — в [своём канале](https://t.me/gromovyna/24) он рекомендует её всем, кто
хочет разобраться в этом шифре.

## Что такое KeeLoq

KeeLoq — блочный шифр на основе NLFSR (регистр сдвига с нелинейной обратной связью), разработан компанией
Nanoteq Pty Ltd. и продан Microchip Technology Inc. Шифрует **блоки по 32 бита** **64-битным ключом** за
**528 итераций**. Реализует *code hopping* (переключение кода): каждая передача — уникальный пакет.

### Структура пакета

64-битный пакет KeeLoq, например `239B3DEBF16C47A6`:

- **Fix** (первые 4 байта, `239B3DEB`) — фиксированная часть, передаётся открыто: ID нажатой кнопки (`2`) и
  28-битный серийный номер пульта (`39B3DEB`).
- **Hop** (следующие 4 байта, `F16C47A6`) — динамическая часть, зашифрована мануфактурным ключом. В расшифрованном
  виде: `21EB000A` — тот же ID кнопки (`2`), 12 бит дополнительной информации (зачастую `serial & 0x3FF`) и сам
  **16-битный счётчик нажатий** (`000A`).

![Структура пакета KeeLoq](/img/remote/167cc7293a53adb1.png)

Именно это Флиппер показывает после [Read](/ru/subghz/read): `Fix`, `Hop`, `Btn`, `Cnt` и имя производителя.

### Логика счётчика

- Переданное значение соответствует ожидаемому в EEPROM приёмника → приёмник подаёт сигнал контроллеру (ворота
  открываются).
- Значение **больше** сохранённого → приёмник синхронизируется с ним и после следующей передачи работает штатно.
- Значение **меньше** → команда игнорируется, а некоторые приёмники после нескольких «устаревших» значений вовсе
  отвязывают пульт. *Собственно, это и есть опасность при экспериментах с KeeLoq.* См. [Динамические коды](/ru/subghz/rolling-codes).

## Режимы безопасности (learning)

Ключ, которым реально шифруется hop, получается из **мануфактурного ключа** (64 бита, общий для пультов одного
производителя/линейки). В стандарте три режима (они же KDF, learnings):

| Режим | Как получается ключ пульта |
|---|---|
| **Simple learning** (простой) | мануфактурный ключ используется как есть (наименее защищённый) |
| **Normal learning** (классический) | мануфактурный ключ преобразуется серийным номером пульта побитовыми операциями |
| **Secure learning** (безопасный) | вместо серийника используется дополнительное значение — **seed**, уникальное для пульта и передающееся при первоначальной привязке (самый защищённый из стандартных) |

Некоторые производители реализуют свои режимы: **Magic XOR Type-1** (Beninca — XOR серийного номера на
мануфактурный ключ) или **FAAC SLH (SPA)** — серия побитовых операций и шифрования, по мнению li0ard самый
продуманный.

::: tip Unleashed
Unleashed реализует все стандартные режимы и множество фирменных (`lib/subghz/protocols/keeloq_common.h`):
Simple, Normal, Secure, Magic XOR type 1, FAAC, Magic Serial типов 1–3, KingGates, Jarolift, Erreka, Pujol, AERF,
JCM, JCM Gen2, Stagnoli и табличный Telcoma. Более 100 производителей — в [Поддерживаемых системах](/ru/subghz/supported-systems).
:::

## Мануфактурные ключи в Unleashed

Чтобы декодировать сигнал KeeLoq, Флипперу нужен мануфактурный ключ. Unleashed хранит их в **зашифрованной** базе
на SD-карте:

| Файл | Назначение |
|---|---|
| `/ext/subghz/assets/keeloq_mfcodes` | встроенные ключи, зашифрованы (`Encryption: 1`), обновляются вместе с прошивкой |
| `/ext/subghz/assets/keeloq_mfcodes_user` | **ваши** ключи, открытым текстом (создайте из `keeloq_mfcodes_user.example`) |

При декодировании перебираются все ключи; при успехе показывается имя: `KL: DoorHan`, `KL: Nice_Smilo` и т.п.
Если ни один ключ не подошёл — сигнал отображается как **`KL: Unknown`**: его можно сохранить, но нельзя отправить
или сгенерировать следующий код. CLI-команды `subghz`, которые декодируют сигналы, при запуске выводят
`Load_keystore keeloq_mfcodes OK` и `Load_keystore keeloq_mfcodes_user OK` / `Absent` — удобная проверка, что базы
грузятся.

### Формат пользовательского файла

```text
# AABBCCDDEEFFAABB:X:NAME
# AABBCCDDEEFFAABB - мануфактурный ключ, 64 бита
# X - тип learning: 1 - Simple, 2 - Normal, 3 - Secure, 4 - Magic_xor_type1,
#     5 - FAAC SLH, 6 - Magic Serial typ1, 7 - Magic Serial typ2, 8 - Magic Serial typ3,
#     0 - перебор previous и man в прямом и обратном порядке байт
# NAME - имя (без пробелов), до 64 символов
Filetype: Flipper SubGhz Keystore File
Version: 0
Encryption: 0
AABBCCDDEEFFAABB:1:Test1
AABBCCDDEEFFAABB:1:Test2
```

В конце файла оставьте пустую строку. Файл `_user` не перезаписывается при обновлении.

### Поля `Manufacture` и `Seed`

В сохранённом `.sub` KeeLoq производитель записан по имени:

```text
Protocol: KeeLoq
Bit: 64
Key: DE AD BE EF CA FE BA BE
Manufacture: DoorHan
```

Системы с secure learning также хранят `Seed: XX XX XX XX`. Если вручную дописать строки `Seed` и `Manufacture` в
файл, который читается как `KL: Unknown`, он станет декодируемым (см. BFT/Erreka ниже).

## Seed: BFT Mitto, Erreka, FAAC SLH, Genius

Эти системы используют **seed** — уникальный для пульта (или для всей инсталляции). Без него сигнал читается как
`KL: Unknown` (или не декодируется вовсе), и пульт, который примет приёмник, создать нельзя.

- **BFT Mitto** — у новых пультов seed вычисляется из серийника, они сразу читаются в Read (`KL: BFT`). У старых
  seed уникальный. Переведите оригинал в режим программирования (отверстие сзади или кнопки 1+2): он отправит
  пакет, у которого `Fix` начинается с `F`; **`Hop` этого пакета и есть seed** в открытом виде.
- **Erreka IRIS** — замкните контакты `1` и `5` пятиконтактного разъёма сбоку: опять `Fix` начинается с `F`, а
  `Hop` — seed. В некоторых инсталляциях seed **у всех** пультов один — тогда новый пульт должен использовать его же.
- **FAAC SLH / Genius** — seed читается с **мастер**-пульта в режиме программирования; он **разный для каждой
  кнопки**.
- Нет программирующей кнопки? Используйте приложение **[Seed Capturer](/ru/subghz/seed-capturer)**: оно собирает
  последовательные пары Fix/Hop, а seed восстанавливается в приложении-компаньоне qUnleashed.

С seed создайте пульт в `Sub-GHz → Add Manually [Advanced]` (SERIAL → BUTTON → COUNTER → SEED), см.
[Add Manually](/ru/subghz/add-manually) и [привязку пультов](/ru/subghz/remote-prog).

## Известные атаки (обзор)

Из статьи li0ard — для понимания, не инструкция.

**Теоретические:** слайд-атака (порядка 2³² пар открытый/шифротекст, даёт первые 32 бита ключа), корреляционный
подход (использует смещение 5/8 у NLFSR), линейный шаг (последние 16 бит ключа, если известны предыдущие). Общая
сложность ≈ 2⁵².

**Практические** (благодарность Derek Jamison за материалы и приложение «SubGHz Rolling Flaws»):

| Атака | Суть |
|---|---|
| Replay | повтор пойманного пакета; работает для статики и уязвимых приёмников, не проверяющих счётчик |
| Клонирование пульта | зная мануфактурный ключ, можно сделать рабочую копию — но будет конфликт счётчиков с оригиналом, вплоть до отвязки |
| Future | отправить «будущее» значение счётчика (`0001` → `3E91`); приёмник синхронизируется, оригинал рассинхронизирован |
| Rollback | откатить счётчик после нескольких использований; редкие приёмники заново синхронизируются |
| Rolljam | записывать сигналы, глуша приёмник, и использовать позже. **Глушение незаконно** почти во всех странах (в т.ч. США, ЕС, РФ) |
| Атака на мануфактурные ключи (KGB) | приёмник может принимать несколько мануфактурных ключей; отправить fix оригинала со счётчиком, закодированным другим ключом |
| Enc00 | подменить fix на fix другого привязанного пульта и использовать hop оригинала; пульт, чей fix использован, рассинхронизируется |
| Unknown | если приёмник не может декодировать hop, он использует 0; универсальные приёмники могут открыться при значении 0 |

Несмотря на всё это, KeeLoq, как и Mifare Classic (чей Crypto-1 взломан ещё в 2000-х), остаётся популярным в
бюджетных системах; часть производителей (Beninca, Hormann) уже перешла на AES.

::: warning
Экспериментируйте только со своими пультами и приёмниками. Рассинхронизированный или отвязанный пульт может
потребовать повторной привязки к приёмнику.
:::

## Проблемы и решения

- **`KL: Unknown`** — подходящего ключа нет. Проверьте модуляцию, обновите прошивку (новые ключи) или добавьте
  ключ в `keeloq_mfcodes_user`, если он законно у вас есть. Для систем с seed — восстановите seed.
- **Декодируется, но приёмник игнорирует Флиппер** — вы отправляете клон; см. [Динамические коды](/ru/subghz/rolling-codes)
  и [Режимы счётчика](/ru/subghz/counter-mode).
- **`Function requires an SD card with fresh databases.`** в Add Manually — нет базы ключей; переустановите прошивку
  со вставленной SD-картой.
