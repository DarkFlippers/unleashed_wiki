# Режимы счётчика (Counter Mode, экспериментально)

**Counter Mode** меняет то, как растёт динамический счётчик, когда Флиппер передаёт сохранённый сигнал. Цель —
клон оригинального пульта, который **не конфликтует** с ним, чтобы и Флиппер, и оригинал работали с одним
приёмником без рассинхронизации. (Теория: [Динамические коды](/ru/subghz/rolling-codes).)

::: tip Unleashed
Режимы счётчика есть только в Unleashed. Поддерживаемые протоколы: **Nice FloR-S, CAME Atomo, Alutech AT-4N,
KeeLoq, V2 Phoenix**.
:::

::: danger Прочитайте перед использованием
Не экспериментируйте с оборудованием, к которому у вас нет доступа. Если вы не уверены, какой режим подходит, и
**не можете заново привязать оригинальный пульт** к приёмнику — не используйте эти режимы: пульт может
рассинхронизироваться или перестать приниматься. Если можете проверить на своём приёмнике — расскажите команде
Unleashed, что сработало (GitHub issues / чаты сообщества).
:::

## Как задать режим

### Способ 1 — правка `.sub`-файла

1. Скопируйте файл из `/ext/subghz/` на ПК (qFlipper, мобильное приложение или картридер).
2. Добавьте в конец строку:
   ```text
   CounterMode: X
   ```
   где `X` — номер режима. Пробел после двоеточия обязателен.
3. Скопируйте файл обратно.

```text
Filetype: Flipper SubGhz Key File
Version: 1
Frequency: 433920000
Preset: FuriHalSubGhzPresetOok650Async
Protocol: Nice FloR-S
Bit: 52
Key: AA AA AA AA AA AA AA
CounterMode: 1
```

### Способ 2 — Signal Settings на Флиппере

При включённом **Debug** в меню сохранённого сигнала появляется пункт
`Sub-GHz → Saved → <файл> → Signal Settings`. В строке `Counter Mode` можно выбрать `System` (режим 0)
или `Mode 1` … до последнего режима протокола — выбор сразу записывается в файл. На том же экране
правятся счётчик и код кнопки: см. [Signal Settings](/ru/subghz/signal-settings).

## Режимы по протоколам {#modes-by-protocol}

Режим 0 — всегда по умолчанию: обычный пульт, счётчик растёт на глобальное значение
[Counter Incr.](/ru/subghz/settings) (по умолчанию +1) и сбрасывается в 0 после `0xFFFF`.

### Nice FloR-S

| Режим | Счётчик | Примечание |
|---|---|---|
| 0 | +множитель | по умолчанию |
| 1 | `0x0001 / 0xFFFE` | приёмник **floxi2r** |
| 2 | `0x0000 / 0x0001` | приёмник **ox2** |

### CAME Atomo

| Режим | Счётчик | Примечание |
|---|---|---|
| 0 | +множитель | по умолчанию |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` | работает с внешним CAME **RE432**, возможно и с другими |
| 2 | `0x807B / 0x807C / 0x007B / 0x007C` | работает с внешним CAME **RE432**, возможно и с другими |
| 3 | заморожен | счётчик не увеличивается |

### Alutech AT-4N

| Режим | Счётчик | Примечание |
|---|---|---|
| 0 | +множитель | по умолчанию |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` | приёмник **MCSW-3.3M** |
| 2 | `0x0000 … 0x0005` | другие платы приёмников |

### KeeLoq

| Режим | Счётчик | Примечание |
|---|---|---|
| 0 | +множитель | по умолчанию |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` | может работать с некоторыми системами |
| 2 | `+0x3333` за передачу (13107) | например DoorHan |
| 3 | `0x8006 / 0x8007 / 0x0006 / 0x0007` | например Hormann EcoStar |
| 4 | `0x807B / 0x807C / 0x007B / 0x007C` | например Nice Smilo |
| 5 | `0x0000 / 0xFFFF` | чередует 0 и 65535 |
| 6 | заморожен | счётчик не увеличивается |
| 7–10 | пакеты принудительной синхронизации | DoorHan, Phantom / Hiland, см. ниже |

#### Режимы 7–10: пакеты принудительной синхронизации (DoorHan, Phantom / Hiland)

Эти режимы не меняют счётчик — каждое нажатие отправляет **фиксированный пакет** кодов. Приёмник
синхронизируется, только когда слышит две передачи с **последовательными** счётчиками, поэтому пакет состоит из
последовательных пар, расставленных так, чтобы каждый шаг оставался в окне синхронизации приёмника, а пары вместе
покрывали всё пространство счётчика. Это возвращает приёмник из любого состояния. Счётчик в файле не меняется,
поэтому каждое нажатие шлёт тот же пакет, и файл остаётся рабочим.

Каждый пакет код в код повторяет то, что шлёт пульт-клон для этого семейства плат. Режимы 7–9 — клон DoorHan
Smart, режим 10 — клон Phantom / Hiland. `X` — счётчик в вашем файле.

| Режим | Для чего | Пакет | Время на нажатие |
|---|---|---|---|
| 7 | самые старые платы DoorHan | 12 кодов: `X / X+1`, четыре пары с шагом 15998 вперёд (кнопка 0), затем `X-2 / X-1`; первая и последняя пары — с вашей кнопкой | ~1,3 с |
| 8 | DHRE, большинство новых плат, клоны распашных ворот | 12 кодов: `X / X+1`, четыре пары через `+0x3334`, затем снова ваш счётчик, где срабатывает `X+1` с вашей кнопкой | ~1,3 с |
| 9 | платы роллет CV01 и другие старые | 3 кода с вашей кнопкой: `X + 0x8000`, `X-1`, `X+1`, каждый дважды | ~0,65 с |
| 10 | Phantom / Hiland | 2 кода с вашей кнопкой: абсолютные `0xFFFE`, `0xFFFF`, каждый трижды | ~0,4 с |

::: warning Режим 7 изменился
Режим 8 — это ровно то, что делал `CounterMode: 7` в прошлых релизах. Если у вас был работающий файл с
`CounterMode: 7`, замените на `CounterMode: 8`.
:::

Подробности:

- В длинных пакетах (7 и 8) каждый код уходит **один раз** (оригинальный клон шлёт каждый два-три раза): весь
  пакет собирается в памяти, и утроение потребовало бы 20 КБ вместо 8 КБ. Повторная отправка пакета — не замена:
  уже синхронизированный приёмник воспримет второй проход как новый и снова сработает, а повтор одного кода подряд
  он игнорирует как дубль.
- Режим 10 игнорирует счётчик в файле. Без «прохода» одно нажатие синхронизирует приёмник, хранящий любое значение
  в 32768 значениях ниже `0xFFFE` — там, где оказывается приёмник, ушедший вперёд относительно пульта. Не
  сработало — отправьте ещё раз.
- **Удержание** Send повторяет пакет, пока держите; приёмник, синхронизированный первым проходом, воспримет это как
  ещё одно нажатие. Повторное нажатие Send во время отправки пакета **прерывает** его.

### V2 Phoenix (Phox)

| Режим | Счётчик | Примечание |
|---|---|---|
| 0 | +множитель | по умолчанию |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` («как ofex») | проверено, работает |
| 2 | `0x0000 … 0x0004` | может работать |

## Пример: KeeLoq DoorHan с +0x3333

```text
Filetype: Flipper SubGhz Key File
Version: 1
Frequency: 433920000
Preset: FuriHalSubGhzPresetOok650Async
Protocol: KeeLoq
Bit: 64
Key: DE AD BE EF CA FE BA BE
Manufacture: Doorhan
CounterMode: 2
```

## Проблемы и FAQ

- **После добавления `CounterMode` файл не работает** — проверьте синтаксис `CounterMode: X` (пробел после
  двоеточия) и допустим ли номер для протокола.
- **Неверный номер режима?** Используется последний режим из списка протокола.
- **Нужно ли добавлять в каждый файл?** Нет. Без `CounterMode` используется режим 0.
- **Может ли это повредить пульт/приёмник?** Может рассинхронизировать пульт — зависит от приёмника. Не
  используйте, если не можете перепривязать оригинал.
- **Какой режим выбрать?** Если не уверены — никакой. Лучше [создайте новый пульт](/ru/subghz/add-manually).
