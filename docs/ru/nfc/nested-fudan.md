# Гайд по Nested-атакам и бэкдорам Fudan для Flipper

Итак, в релизе **1.1.2** официальной прошивки Флиппера одним из важных функциональных изменений стало то, что в
стабильную ветку попали изменения [@noproto](https://github.com/noproto), связанные со «встраиванием» Nested-атак в
стандартный флоу `NFC → Read` (в Unleashed всё это тоже есть). Во время разработки этих фичей один ресёрчер из
комьюнити сделал важные открытия — атака на **static encrypted nonces** и **нахождение бэкдор-ключей в чипах
производства Fudan** (и не только), которые позволяют прочитать сектора метки Mifare Classic, даже не имея к ним
ключей. Все эти изменения были адаптированы и попали в прошивку, как и реализация атак в приложении **MFKey (версии 3)**,
сейчас — [MFKey 4.1](/ru/nfc/mfkey-app). Здесь — практическая работа с этими фичами на уровне «что тут нажимать», а
кому интересен сам ресёрч — [ссылка на статью](https://eprint.iacr.org/2024/1275.pdf).

*Автор: @gromovyna.*

::: tip Update, сентябрь 2026
Если вы просто ищете способ быстро восстановить криптоключи для меток Mifare Classic, гляньте также, как это можно
сделать с помощью приложения-компаньона **qUnleashed**: [Быстрое вскрытие ключей с qUnleashed](/ru/nfc/qunleashed).
:::

## Краткое описание

**Nested-атаки** — атаки типа «chip only», т.е. без использования ридера, которые позволяют восстановить неизвестные
криптоключи (дальше КК), зная хотя бы один из КК метки. Концептуально метки можно поделить на 4 типа (технически
правильно говорить, что есть Nested и HardNested, но для простоты понимания делим так):

| Метка уязвима к | Тип нонсов | Где считается ключ |
|---|---|---|
| **Nested** | weak PRNG | MFKey на Флиппере, qUnleashed |
| **HardNested** | PRNG: hard | qUnleashed или ПК (не на Флиппере) |
| **Static Nested** | static nonce | MFKey на Флиппере, qUnleashed |
| **Static Encrypted Nested** (SEN) | static encrypted nonce | MFKey на Флиппере (самый медленный), qUnleashed |

**Backdoor-ключи** — криптоключи, позволяющие получить доступ к данным метки, не обладая реальными КК метки.

Для примеров автор использовал метки, уязвимые к атакам каждого типа. Для них сгенерирована пара КК A и B:
**A3F92C8E7D3A** и **4F6D91C5BA7E**, ими зашифрован сектор 0 (биты доступа дефолтные). На Proxmark3 метка выглядела
так:

![Проверка на стандартные ключи на Proxmark3](/img/remote/86130b06142278a1.png)

## 1. Читаем метку

Для работы с меткой заходим в `Main Menu → NFC → Read`.

### 1.1 Метка оказалась с бэкдором

Если мы видим следующие скрины:

![Backdoor Read](/img/remote/1491507f521c09f5.png)

![Чтение через бэкдор](/img/remote/e9be977d84486794.png)

и ещё пару скринов после с надписью **(Backdoor)** в названии — значит, метка с бэкдором: ФЗ считает данные из
секторов и соберёт нонсы, чтобы можно было восстановить ключи. Типичная ситуация после такого — все сектора
прочитаны, но ключей меньше, чем нужно.

![Все сектора, но только 30 ключей](/img/remote/9e7db33e51594779.png)

### 1.2 Метка без бэкдора

Если же метка оказалась без бэкдора, процесс пойдёт через классический подбор ключа — сначала из пользовательского,
потом из системного словаря.

![Пользовательский словарь](/img/remote/fff8f5662df941b9.png)

![Системный словарь](/img/remote/0da64f609fc2c770.png)

После этого, если хоть один ключ был найден, метка перейдёт в режим анализа **PRNG** и пройдётся по **Nested
Dictionary**:

![PRNG Analysis](/img/remote/3e0e493fe7fcbd5f.png)

затем — **Calibration** и сбор нонсов (**Nonce Collection**):

![Калибровка и сбор нонсов](/img/remote/f5b036a96f5a0869.png)

Если метка уязвима только к HardNested-атаке, сбор нонсов займёт больше времени, а в заголовке будет **(Hard)**:

![Сбор nonce для метки с hard PRNG](/img/remote/fca9f1b2e4475631.png)

> В таком случае можно идти сразу в [пункт 2.2](#_2-2-метка-уязвима-к-hardnested).

Результат будет более привычен: количество найденных на этом этапе ключей будет приближено (зависит от битов
доступа) к количеству прочитанных секторов.

![Результат после nested](/img/remote/d15656101dfafcc4.png)

Все собранные нонсы дописываются в `/ext/nfc/.nested.log`.

## 2. Восстанавливаем ключи

Для этого идём в `Main Menu → Apps → NFC → MFKey`.

::: warning Проверьте версию
Убедитесь, что версия приложения нужная и не перетёрта старой, если вы игрались с приложениями или доставляли его
отдельно. В Unleashed — **MFKey 4.1**.
:::

![MFKey](/img/remote/195a1b6a411e7bf3.png)

Жмём <kbd>OK</kbd> **Start** и…

### 2.1 Метка уязвима к Nested, Static Nested, Static Encrypted Nested

Запускается процесс взлома — можно оставить Флиппер и заняться делами:

![Процесс взлома](/img/remote/a514db67a986ae2c.png)

Остаётся только ждать. На железе Флиппера этот процесс, увы, не быстрый (привет работе по SPI) и зависит от ряда
факторов:

- по скорости применимой атаки: Nested < Static Nested < Static Encrypted Nested (SEN самый медленный);
- от количества неизвестных КК, которые надо вычислить (чем меньше, тем быстрее);
- от уникальности используемых КК: ключ, переиспользуемый везде, найдётся быстрее, чем частично
  диверсифицированный тег (например, Iron Logic), который найдётся быстрее, чем полностью диверсифицированный тег
  (например, от филамента Bambu Lab).

К сожалению, UI ведёт себя не всегда отзывчиво, бывает «задумывается». Иногда Флиппер может казаться зависшим (но не
советую спешить и бездумно его будить). Можно ориентироваться на строчку **RAM**, которая будет мигать.

::: tip Update, сентябрь 2026
Автор надеялся, что по аналогии с MFKey32 эти атаки портируют в мобильное приложение Flipper и ключи можно будет
находить быстрее на телефоне. Теперь уже не надеется — хочешь сделать хорошо, сделай сам: в приложении-компаньоне
**qUnleashed** реализованы все атаки, включая **hardnested**. Подробно — [в статье](/ru/nfc/qunleashed).
:::

::: warning Важно: static encrypted nonce
В случае атаки на метку со Static Encrypted Nonce, из-за специфики атаки, процесс не маркает нонсы как «решённые», а
только строит предположения (генерирует ключи, которые надо будет проверить), и приложение может «зависнуть» на
последнем (или более раннем) шаге. Если прошло достаточно времени, можно выйти и проверить результат (см. пункт 3).
Начиная с MFKey 4.x кандидаты сохраняются в **CUID-словарь** метки `/ext/nfc/assets/mf_classic_dict_<UID>.nfc`,
который `Read` пробует первым.
:::

После завершения расшифровки мы получим соответствующую информацию и количество КК, добавленных в пользовательский
словарь (**Keys added to user dict: N**, а для SEN — **SEN key candidates: N**).

![MFKey: Complete](/img/remote/c9ef77139b74cc89.png)

Можно переходить к повторному чтению метки, описанному в пункте 3.

### 2.2 Метка уязвима к HardNested

Это можно было определить по соответствующему экрану во время сбора нонсов, или же MFKey покажет ошибку, что нонсы
не найдены:

![MFKey: No nonces found](/img/remote/2519c7dce0b881c9.png)

HardNested — единственная атака, которую нельзя реализовать на Флиппере. Варианты:

- **qUnleashed** (рекомендуется, телефон или ПК): `Tools → Recover MIFARE Keys`, см. [qUnleashed](/ru/nfc/qunleashed).
  Ключи сразу попадают в пользовательский словарь.
- **Компьютер с HardnestedRecovery**, как в оригинальном гайде:
  1. Перекиньте на компьютер файл `.nested.log`, он лежит по пути `/ext/nfc/.nested.log` (папка `nfc` на карте
     памяти Флиппера).
  2. Склонируйте репозиторий [github.com/noproto/HardnestedRecovery](https://github.com/noproto/HardnestedRecovery) и
     соберите командой `make build`. Как собирать на конкретной ОС — вне этого гайда, но для Windows можно
     использовать WSL или Docker (оверкилл, но работает).
  3. Запустите, передав путь к файлу параметром:

     ```bash
     ./hardnested_main .nested.log
     ```

  4. Найденные ключи видны в логе:

     ```text
     [=] Hardnested attack starting...
     [=]    0 |    0 | Start using 32 threads                 |                 |
     [=]    0 |    0 | Brute force benchmark: 589 million (2^29.1) keys/s   | 140737488355328 |  3d
     [=]   16 |  256 | Loading nonces from file                |     24286058496 |  41s
     [=]   46 | 1891 | Apply Sum property. Sum(a0) = 128            |      1262183296 |  2s
     [=]   78 | 1894 | Brute force phase completed. Key found: A3F92C8E7D3A  |               0 |  0s
     Key found for UID: c66d2df2, Sector: 0, Key type: A: a3f92c8e7d3a
     ...
     [=]   70 | 1218 | Brute force phase completed. Key found: 4F6D91C5BA7E  |               0 |  0s
     Key found for UID: c66d2df2, Sector: 0, Key type: B: 4f6d91c5ba7e
     ```

::: danger Важно
В отличие от случаев из 2.1, ключи, найденные HardnestedRecovery на ПК, надо добавить в пользовательский словарь
**вручную**: `NFC → Extra Actions → MIFARE Classic Keys → Add` или дописать в
`/ext/nfc/assets/mf_classic_dict_user.nfc`.
:::

## 3. Перечитываем метку снова

После расшифровки ключей прочитайте метку снова через `NFC → Read`.

::: tip Pro-совет
Если вы сохраняли метку после первого чтения, анлокнуть её можно из меню сохранённой метки:
`Saved → <метка> → Unlock with Dictionary`.
:::

![Unlock with Dictionary](/img/remote/8232d690446c70b6.png)

::: tip Pro-совет
Для ускорения последующей работы рекомендуется подчищать `.nested.log` после того, как вы взломали КК к метке.
:::
