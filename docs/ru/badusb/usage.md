# Работа с Bad USB

Названия пунктов и сообщения ниже — ровно такие, как в прошивке.

::: warning
Запускайте скрипты только на своих компьютерах или там, где вам разрешили. Читайте скрипт перед запуском: он
сделает всё, что в нём написано, с правами вашего пользователя.
:::

## Перед началом

- Нужна microSD-карта с ресурсами прошивки. Без неё приложение пишет *«No SD card or app data found. This app will
  not work without required files.»*
- Положите скрипт (`.txt`) в `/ext/badusb/` (подпапки тоже можно).
- **Режим USB забирает USB-порт Флиппера.** Если по USB подключён qFlipper или [CLI](/ru/dev/cli), приложение покажет
  *«Connection Is Active! Disconnect from PC or phone to use this function.»* Сначала закройте qFlipper.

## Основной экран

1. Откройте `Main Menu → Bad USB`.
2. Выберите скрипт в файловом браузере. Откроется экран скрипта.

В верхней строке — имя скрипта, ниже в скобках раскладка, `(default)` или, например, `(de-DE)`, и прошедшее время,
а в режиме BLE — PIN сопряжения. Картинка в центре — USB-штекер или значок Bluetooth.

![Экран скрипта Bad USB: загружен demo_windows, 0/34 строк, подсказки Config / Run / BLE](/screens/badusb/script_ready.png)

| Состояние | Текст на экране | <kbd>OK</kbd> | <kbd>←</kbd> | <kbd>→</kbd> |
|---|---|---|---|---|
| Ожидание / Готово / не подключено | прогресс или *Connect to device* | **Run** | **Config** | переключить на **BLE** / **USB** |
| Ждёт подключения после Run | *Will run on connect* | **Cancel** | | |
| Выполняется или идёт `DELAY` | `строка/всего`, проценты, `Delay Ns` | **Stop** | | **Pause** |
| Пауза | *Paused* | **End** | | **Resume** |
| Ожидание на `WAIT_FOR_BUTTON_PRESS` | | **Press to continue** | | |
| Ошибка | *ERROR:* + `line N` + сообщение | | | |

Если нажать **Run** до того, как хост распознал Флиппер, приложение ждёт (*«Will run on connect»*) и запускает
скрипт само — **через 1,5 с после подключения**, чтобы хост успел установить клавиатуру.

Пока хост не подключён, вместо прогресса показываются песочные часы и надпись *Connect to device*:

![Bad USB ждёт USB-хост, на экране Connect to device](/screens/badusb/not_connected.png)

<kbd>Back</kbd> закрывает экран скрипта и возвращает в файловый браузер.

## Запуск по USB

1. Закройте qFlipper на компьютере.
2. `Main Menu → Bad USB` → выберите скрипт.
3. Убедитесь, что на экране картинка **USB**; если нет — нажмите <kbd>→</kbd> **USB**.
4. По желанию: <kbd>←</kbd> **Config → Keyboard Layout (global)** — выберите раскладку как на компьютере (по
   умолчанию `en-US`).
5. Подключите Флиппер к компьютеру USB-кабелем.
6. Нажмите <kbd>OK</kbd> **Run**. Прогресс `строка/всего` дойдёт до 100 %.

![Bad USB выполняет скрипт: 32 %, строка 12 из 34, подсказки Stop и Pause](/screens/badusb/script_running.png)

![Bad USB в режиме USB](/img/remote/d49323518c0b4b18.jpg)

## Запуск по Bluetooth (BLE)

1. Убедитесь, что Bluetooth на Флиппере включён (`Settings → Bluetooth`).
2. `Main Menu → Bad USB` → выберите скрипт.
3. Нажмите <kbd>→</kbd> **BLE** — появится значок Bluetooth. Флиппер начнёт рекламироваться как клавиатура.
4. На компьютере/телефоне откройте настройки Bluetooth и подключитесь к **`BadUSB <имя вашего Флиппера>`** (имя по
   умолчанию).
5. Подтвердите сопряжение на обоих устройствах. В режиме по умолчанию на обоих экранах показывается один и тот же
   PIN — проверьте, что он совпадает. PIN также виден на экране скрипта.
6. Нажмите <kbd>OK</kbd> **Run**.
7. Чтобы потом удалить сопряжение: <kbd>←</kbd> **Config → Remove BLE Pairing**, и забудьте устройство на хосте.

![Bad USB в режиме BLE](/img/remote/083420027c3f836c.jpg)

::: tip Отдельная идентичность и сопряжение
В режиме BLE Флиппер использует **свой MAC-адрес** (выводится из MAC Флиппера) и отдельное хранилище сопряжений,
независимое от обычного Bluetooth-профиля. Поэтому сопряжение компьютера с Bad USB не ломает связь с Flipper
Mobile App. При выходе из приложения обычный Bluetooth-профиль восстанавливается.
:::

## Скрипты, которые сами переключают режим

Если **первая строка** скрипта — команда `ID` (USB) или `BLE_ID` / `BT_ID` (Bluetooth), приложение при открытии
скрипта само переключается в этот режим и применяет указанную идентичность. Вручную переключиться через
<kbd>→</kbd> всё равно можно. См. [Формат скриптов → Device ID](/ru/badusb/script-format#device-id).

## Меню Config

<kbd>←</kbd> **Config** доступно, только пока скрипт не выполняется. Содержимое зависит от текущего режима.

### Общее

| Пункт | Значения | Что делает |
|---|---|---|
| **Keyboard Layout (global)** | файловый браузер | Выбор `.kl` из `/ext/badusb/assets/layouts/`. Действует на все скрипты, которые не задают свою раскладку через `DUCKY_LANG`. См. [Раскладки клавиатуры](/ru/badusb/layouts). |
| **Connection** | `USB` / `BLE` | То же, что <kbd>→</kbd> на основном экране. Список ниже меняется соответственно. |

### Режим BLE

| Пункт | Значения | Что делает |
|---|---|---|
| **Persist Pairing** | `ON` / `OFF` | ON (по умолчанию): запомнить хост (bonding), он будет переподключаться без повторного сопряжения. OFF: сопрягаться каждый раз. |
| **Pairing Mode** | `YesNo`, `PIN Type`, `PIN Y/N` | `YesNo` — сопряжение без PIN. `PIN Type` — Флиппер показывает PIN, который вы вводите на хосте. `PIN Y/N` (по умолчанию) — PIN на обоих экранах, подтвердите совпадение. |
| **Set Device Name** | текст | Bluetooth-имя (*«Set BLE device name»*). Пусто = `BadUSB <имя Флиппера>`. |
| **Set MAC Address** | 6 байт | *«Set BLE MAC address»*. |
| **Randomize MAC Address** | действие | Генерирует случайный статический MAC, показывает **Done**. Удобно, чтобы выглядеть как «новая» клавиатура. |
| **Restore BLE Defaults** | действие | Сбрасывает имя и MAC, Persist Pairing ON, Pairing Mode `PIN Y/N`. |
| **Remove BLE Pairing** | действие | *«Unpair the Device?»* → **Unpair** забывает все хосты, сопряжённые с Bad USB. |

### Режим USB

| Пункт | Значения | Что делает |
|---|---|---|
| **Set Manufacturer Name** | текст | Строка производителя USB (*«Set USB manufacturer name»*). |
| **Set Product Name** | текст | Строка продукта USB (*«Set USB product name»*). |
| **Set VID and PID** | 4 байта | *«Set USB VID:PID»*. Флиппер представится хосту с этими Vendor/Product ID. |
| **Randomize VID and PID** | действие | Случайные VID и PID, показывает **Done**. |
| **Restore USB Defaults** | действие | Сбрасывает VID/PID и имена: используется стандартная клавиатурная идентичность Флиппера. |

Всё это, а также выбранная раскладка и режим, сохраняется в `/ext/badusb/.badusb.settings`. Строка `ID` / `BLE_ID`
в скрипте переопределяет идентичность только для этого скрипта.

## Решение проблем

| Проблема | Что попробовать |
|---|---|
| Набирается мусор (`z` и `y` перепутаны, не те символы) | Раскладка хоста не совпадает с раскладкой приложения. Выберите нужную в Config или добавьте `DUCKY_LANG` в скрипт. Если на ПК несколько языков ввода, перед запуском переключите хост на язык раскладки (например, английский, а не русский). |
| Пропадают символы | Хост не успевает. Добавьте `DEFAULT_STRING_DELAY 10` (или больше) и подлиннее `DELAY` после открытия окон. |
| Скрипт начинает печатать до открытия окна | Увеличьте `DELAY` после `GUI r`, `ENTER` и т. п. |
| *ERROR: line N* | В строке неизвестная команда, опечатка, неверное число или не-ASCII текст. Команды **чувствительны к регистру** (`STRING`, а не `string`). См. [Формат скриптов](/ru/badusb/script-format). |
| *Native .kl supports ASCII, not UTF-8* | В `STRING` есть не-ASCII символы (кириллица, диакритика…). В Windows используйте `ALTSTRING`/`ALTCHAR` или вводите такой текст иначе. |
| *Connection Is Active!* | Отключите qFlipper / CLI от USB-порта. |
| macOS открывает *Keyboard Setup Assistant* | Используйте строку `ID` с VID/PID клавиатуры Apple (см. пример `demo_macos.txt`) или просто закройте ассистент. |
| BLE-хост не находит Флиппер | Включите Bluetooth на Флиппере, оставайтесь на экране скрипта в режиме BLE, удалите старые сопряжения с обеих сторон (`Remove BLE Pairing`). |
