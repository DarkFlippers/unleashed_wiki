# FuriHalBus API

Если приложение напрямую работает с периферией микроконтроллера (таймеры, АЦП, DMA, …), оно обязано включать и
выключать её тактирование через **FuriHalBus**. Ошибка здесь намеренно роняет Флиппер, поэтому прочитайте эту
страницу, прежде чем писать низкоуровневый код.

## Основы

При старте системы большая часть периферии находится **в сбросе и без тактирования**. Это экономит энергию и
гарантирует, что перед использованием периферия всегда в известном состоянии. Часть важной периферии система
включает сразу; остальную должен явно включать тот, кто ею пользуется.

> Здесь *«система»* — любой код, относящийся к операционной системе, драйверам железа или встроенным приложениям.

| Вызов | Что делает | Условие — иначе **crash** |
|---|---|---|
| `furi_hal_bus_enable()` | Подать тактирование и вывести периферию из сброса | Периферия должна быть **выключена** (дважды включить нельзя) |
| `furi_hal_bus_disable()` | Вернуть в сброс и остановить тактирование | Периферия должна быть **включена** |
| `furi_hal_bus_reset()` | Сбросить все её регистры в исходное состояние, не выключая | Периферия должна быть **включена** |

Типичное использование:

```c
#include <furi_hal_bus.h>

furi_hal_bus_enable(FuriHalBusTIM1);
// ... configure and use TIM1 ...
furi_hal_bus_disable(FuriHalBusTIM1);
```

## Категории периферии

Встроенная периферия делится на три группы:

1. включается системой при старте и никогда не выключается;
2. включается и выключается системой по необходимости;
3. включается и выключается пользовательским кодом.

### 1. Всегда включённая периферия

Включается системой. Пользовательский код **никогда** не должен её выключать.

| Периферия | Где включается |
|:-:|:-:|
| DMA1, DMA2, DMAMUX | `furi_hal_dma.c` |
| GPIOA, GPIOB, GPIOC, GPIOD, GPIOE, GPIOH | `furi_hal_resources.c` |
| PKA, AES2, HSEM, IPCC | `furi_hal_bt.c` |
| FLASH | включается аппаратно |

### 2. Системная периферия по требованию

Включается и выключается системой. Не используйте её напрямую — пользуйтесь соответствующим API. Если всё же
обходите API, включите периферию сами и выключите, когда закончите.

| Периферия | Заголовок API |
|:-:|:-:|
| RNG | `furi_hal_random.h` |
| SPI1, SPI2 | `furi_hal_spi.h` |
| I2C1, I2C3 | `furi_hal_i2c.h` |
| USART1, LPUART1 | `furi_hal_serial.h` |
| USB | `furi_hal_usb.h` |

### 3. Общая периферия по требованию

По умолчанию выключена. Пользовательский код **обязан** включать её каждый раз, когда к ней обращается. Часть такой
периферии использует и система для отдельных функций — система занимает её только пока соответствующая функция
активна.

| Периферия | Используется системой | Назначение |
|:-:|:-:|:--|
| CRC | | |
| TSC | | |
| ADC | | |
| QUADSPI | | |
| TIM1 | да | subghz, lfrfid, nfc, infrared и др. |
| TIM2 | да | subghz, infrared и др. |
| TIM16 | да | динамик |
| TIM17 | да | cc1101_ext |
| LPTIM1 | да | таймер tickless idle |
| LPTIM2 | да | pwm |
| SAI1 | | |
| LCD | | |

::: warning
Если приложение использует, например, TIM2, пока активен Sub-GHz или Infrared (или наоборот), `furi_hal_bus_enable()`
упадёт, потому что периферия уже включена. Убедитесь, что конфликтующая функция не работает.
:::

## Каналы DMA

`DMA1` и `DMA2` — особый случай: у каждого несколько независимых каналов, и часть из них занята системой.

| DMA | Канал | Используется системой | Назначение |
|:-:|:-:|:-:|:--|
| DMA1 | 1 | да | digital signal |
| DMA1 | 2 | да | digital signal |
| DMA1 | 3 | | |
| DMA1 | 4 | да | pulse reader |
| DMA1 | 5 | | |
| DMA1 | 6 | да | USART_Rx |
| DMA1 | 7 | да | LPUART_Rx |
| DMA2 | 1 | да | infrared, lfrfid, subghz |
| DMA2 | 2 | да | infrared, lfrfid, subghz |
| DMA2 | 3 | да | cc1101_ext |
| DMA2 | 4 | да | cc1101_ext |
| DMA2 | 5 | да | cc1101_ext |
| DMA2 | 6 | да | SPI |
| DMA2 | 7 | да | SPI |

Свободны для своих задач: **каналы 3 и 5 DMA1**.
