# Процесс OTA-обновления

Как Флиппер устанавливает пакет обновления — и как собрать такой пакет самому.

Пользовательская сторона (установка Unleashed через qFlipper, веб-установщик или с SD-карты) описана в разделе
[Обновление](/ru/start/updating). Если обновление сломалось всерьёз, см. [Восстановление](/ru/start/recovery).

## Выполнение кода из RAM

В прошивке есть особый режим загрузки: в **RAM** загружается специально подготовленный образ системы, и
управление передаётся ему. Код, выполняющийся из RAM, имеет полный доступ на запись ко всей флеш-памяти — это
невозможно, пока основная прошивка выполняется из той же флешки. OTA-апдейтер использует этот режим, в том числе
для обновления радиостека на втором ядре микроконтроллера.

## Три этапа

### 1. Бэкап внутренней памяти (`/int`)

`/int` — раздел флеш-памяти Флиппера, занимающий всё место, не занятое прошивкой. Новая прошивка может иметь другой
размер, и её установка переразметила бы флешку с потерей данных. Поэтому прежде всего текущее содержимое `/int`
сохраняется в обычный архив `.tar` на SD-карте.

### 2. Обновление устройства

Основная прошивка загружает в RAM **апдейтер** — специальную сборку прошивки — и запускает его. Апдейтер работает с
системной флешкой согласно манифесту обновления:

1. Если в пакете есть образ **радиостека**, его версия сравнивается с установленной. Если они отличаются, старый стек
   удаляется, а новый записывается и устанавливается. Установку выполняет проприетарная программа ST **FUS** на
   Core2, при этом устройство несколько раз перезагружается.
2. Проверяются и исправляются **Option Bytes** (низкоуровневая конфигурация МК).
3. Загружается файл прошивки `.dfu`, его целостность проверяется по CRC32, он записывается во флешку и сверяется.

### 3. Восстановление внутренней памяти и обновление ресурсов

Система перезагружается в новую прошивку, восстанавливает сохранённое содержимое `/int` и, если в пакете есть архив
ресурсов, распаковывает его на SD-карту.

## Манифест обновления

К каждому пакету прилагается манифест (файл `.fuf`) в формате Flipper File Format — обычный текстовый файл из пар
ключ-значение.

### Обязательные поля (в этом порядке)

| Ключ | Значение |
|---|---|
| `Filetype` | Константная строка `Flipper firmware upgrade configuration` |
| `Version` | Версия манифеста, сейчас `2` |
| `Info` | Произвольное описание пакета |
| `Target` | Аппаратная ревизия, для которой собран пакет |
| `Loader` | Имя файла загрузчика второй стадии, выполняемого из RAM |
| `Loader CRC` | CRC32 файла загрузчика в hex, **little-endian** |

### Необязательные поля

Могут быть пустыми — тогда апдейтер пропускает соответствующие операции.

| Ключ | Значение |
|---|---|
| `Radio` | Имя файла образа радиостека (предоставляется ST) |
| `Radio address` | Адрес установки радиостека (из release notes ST) |
| `Radio version` | Major, minor, sub версия, ветка, релиз и тип стека, упакованные в 6 hex-байт |
| `Radio CRC` | CRC32 образа радиостека |
| `Resources` | Имя архива с ресурсами для SD-карты — `resources.ths`, tar-архив, сжатый heatshrink (см. [Формат tar + heatshrink](/ru/dev/tar-heatshrink)) |
| `OB reference`, `OB mask`, `OB write mask` | Эталонные значения для проверки и исправления option bytes |

## Коды ошибок

Процесс спроектирован максимально отказоустойчивым: ни одна рискованная операция не начинается, пока не проверены
все связанные данные, поэтому устройство не остаётся наполовину обновлённым или «окирпиченным». Если что-то пошло не
так, апдейтер позволяет повторить попытку и показывает код ошибки `[XX-YY]`: `XX` — операция, на которой произошёл
сбой, `YY` — прогресс или подробность.

| Этап | XX | YY | Значение |
|---|--:|---|---|
| Загрузка манифеста | **1** | **13** | Апдейтер сообщил о несовпадении аппаратной версии |
| | | **20** | Не удалось получить сохранённый путь к манифесту |
| | | **30** | Не удалось загрузить манифест |
| | | **40** | Неподдерживаемая версия пакета обновления |
| | | **50** | Пакет для другого аппаратного таргета |
| | | **60** | Отсутствует DFU-файл |
| | | **80** | Отсутствует файл прошивки радиостека |
| Бэкап конфигурации | **2** | **0-100** | Ошибка чтения/записи ФС |
| Проверка прошивки радио | **3** | **0-99** | Ошибка чтения файла прошивки радиостека |
| | | **100** | Несовпадение CRC |
| Удаление прошивки радио | **4** | **0** | Ошибка команды SHCI Delete |
| | | **80** | Ошибка ожидания статуса команды |
| Запись прошивки радио | **5** | **0-100** | Ошибка чтения/записи блока |
| Установка прошивки радио | **6** | **10** | Ошибка команды SHCI Install |
| | | **80** | Ошибка ожидания статуса команды |
| Core2 занят | **7** | **10** | Не удалось запустить C2 |
| | | **20** | Не удалось переключить C2 в режим FUS |
| | | **30** | Ошибка операции FUS |
| | | **50** | Не удалось переключить C2 в режим стека |
| Проверка option bytes | **8** | **yy** | Код option byte |
| Проверка DFU-файла | **9** | **0** | Ошибка открытия DFU-файла |
| | | **1-98** | Ошибка чтения DFU-файла |
| | | **99-100** | DFU-файл повреждён |
| Запись флеш-памяти | **10** | **0-100** | Ошибка чтения/записи блока |
| Проверка флеш-памяти | **11** | **0-100** | Ошибка чтения/записи блока |
| Восстановление конфигурации | **12** | **0-100** | Ошибка чтения/записи ФС |
| Обновление ресурсов | **13-15** | **0-100** | Ошибка чтения/записи SD-карты |

::: tip Что делать при ошибке
- **1-50 / 1-13** — пакет для другого аппаратного таргета: скачайте правильный.
- **2, 12, 13-15** — проблема с SD-картой: проверьте / переформатируйте карту, скопируйте пакет заново.
- **3-100, 9-99/100** — повреждённые файлы: скачайте пакет заново.
- Сначала просто повторите попытку — апдейтер на это рассчитан. Если Флиппер вообще не загружается, используйте
  [Восстановление](/ru/start/recovery).
:::

## Сборка пакетов обновления

Не забудьте передать `DEBUG=0` — см. [Сборка прошивки](/ru/dev/build).

**Полный пакет** — прошивка, радиостек и ресурсы для SD-карты:

```sh
./fbt COMPACT=1 DEBUG=0 updater_package
```

**Минимальный пакет** — только прошивка:

```sh
./fbt COMPACT=1 DEBUG=0 updater_minpackage
```

Результат — в `dist/<target>-<cfg>/`: папка `f7-update-<suffix>` и файл `flipper-z-f7-update-<suffix>.tgz`.

### Другой радиостек

По умолчанию пакеты собираются со стеком **Bluetooth Light**. Если ваша прошивка поддерживает другой стек, передайте
его тип и бинарник:

```sh
./fbt updater_package COMPACT=1 DEBUG=0 COPRO_OB_DATA=scripts/ob_custradio.data COPRO_STACK_BIN=stm32wb5x_BLE_Stack_full_fw.bin COPRO_STACK_TYPE=ble_full
```

`COPRO_OB_DATA` должен указывать на файл в `scripts/` с эталонными данными Option Bytes, соответствующими типу стека.
Иногда нужно ещё подтвердить намерение, добавив `COPRO_DISCLAIMER=...` в командную строку.

### Частичные пакеты

Для произвольного содержимого вызывайте `scripts/update.py` напрямую. Например, пакет, который только устанавливает
стек BLE FULL:

```shell
scripts/update.py generate \
  -t f7 -d r13.3_full -v "BLE FULL 13.3" \
  --stage dist/f7/flipper-z-f7-updater-*.bin \
  --radio lib/stm32wb_copro/firmware/stm32wb5x_BLE_Stack_full_fw.bin \
  --radiotype ble_full
```

Все опции — в `scripts/update.py generate --help`.

## Установка пакета из CLI

Скопируйте распакованную папку пакета на SD-карту и выполните:

```
update install /ext/update/f7-update-local/update.fuf
```

В [CLI](/ru/dev/cli#update) есть также `update backup` и `update restore` для внутренней памяти.
