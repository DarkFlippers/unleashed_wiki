# Аппаратные таргеты

Прошивка модульная: одна кодовая база поддерживает несколько аппаратных конфигураций. Всё, что отличается между
платами — реализация `furi_hal`, код инициализации платы, скрипты линкера, таблицы символов SDK, — собрано в
**описание таргета** (target definition).

В репозитории Unleashed в `targets/` два таргета:

| Папка | Железо |
|---|---|
| `targets/f7` | Flipper Zero — по умолчанию (`TARGET_HW = 7`) |
| `targets/f18` | «Not Flipper Zero» — плата без радиочастей; наследуется от f7 |

Общие заголовки лежат в `targets/furi_hal_include`.

## Как устроен таргет

Каждый таргет — отдельная подпапка в `targets/`. В ней обязательно есть `target.json`, а также любые другие файлы,
на которые ссылается описание. По умолчанию `fbt` компилирует **все исходники** в папке таргета, если они явно не
исключены. Таргеты могут **наследоваться** от другого таргета, чтобы не дублировать код.

## Поля `target.json`

| Поле | Тип | Назначение |
|---|---|---|
| `include_paths` | список строк | Папки (относительно таргета), добавляемые в глобальный путь поиска заголовков C/C++ |
| `sdk_header_paths` | список строк | Папки, заголовки из которых включаются в SDK |
| `startup_script` | имя файла | Startup-скрипт с начальной инициализацией железа |
| `linker_script_flash` | имя файла | Скрипт линкера для основного образа прошивки |
| `linker_script_ram` | имя файла | Скрипт линкера для конфигурации «updater» (работает из RAM) |
| `linker_script_app` | имя файла | Скрипт линкера для файлов `.fap` |
| `sdk_symbols` | имя файла | `.csv` с текущим описанием SDK (API) для таргета |
| `linker_dependencies` | список | Библиотеки, с которыми линкуется прошивка. Не перечисленные **не собираются**. При нескольких проходах линковки одно имя может понадобиться дважды |
| `inherit` | строка | Таргет, от которого берётся базовая конфигурация. Списки дополняются, остальные значения переопределяются |
| `excluded_sources` | список | Файлы из унаследованных конфигураций, которые **не** собирать |
| `excluded_headers` | список | Заголовки из унаследованных конфигураций, которые **не** класть в SDK |
| `excluded_modules` | список | Имена библиотек (модулей) `fbt`, исключаемых при настройке сборки |

## Пример: как f18 наследует f7

`targets/f18/target.json` (в сокращении) показывает наследование и исключения на практике — берёт всё от f7 и
выкидывает драйверы Sub-GHz, NFC, RFID, iButton и инфракрасного порта:

```json
{
    "inherit": "7",
    "include_paths": [
        "furi_hal"
    ],
    "sdk_symbols": "api_symbols.csv",
    "excluded_sources": [
        "furi_hal_infrared.c",
        "furi_hal_nfc.c",
        "furi_hal_rfid.c",
        "furi_hal_subghz.c"
    ],
    "excluded_modules": [
        "nfc",
        "lfrfid",
        "subghz",
        "ibutton",
        "infrared"
    ]
}
```

## Приложения и железо

Не все приложения доступны на всех таргетах.

- **Встроенные приложения:** выберите совместимый набор опцией `FIRMWARE_APP_SET=...`
  (см. [fbt → наборы приложений](/ru/dev/fbt#firmware-app-sets)).
- **Внешние приложения (FAP):** укажите совместимые таргеты в `application.fam` приложения. Например, чтобы
  собирать приложение только для f7, добавьте:

```python
    targets=["f7"],
```

Для других таргетов оно собираться не будет. См. [Манифесты приложений](/ru/dev/app-manifests).

## Сборка под конкретный таргет

Передайте `fbt` параметр `TARGET_HW` (и при необходимости `FIRMWARE_APP_SET`). Например, собрать и прошить по USB
прошивку для f18:

```sh
./fbt TARGET_HW=18 flash_usb_full
```
