# Формат ИК-файлов (`.ir`)

Все ИК-данные на Флиппере хранятся как обычный текст в формате Flipper Format (строки `ключ: значение`).
Расширение — всегда `.ir`. Есть три разновидности, они отличаются только заголовком `Filetype` и назначением.

| Filetype | Для чего | Где |
|---|---|---|
| `IR signals file` | Ваши пульты (записанные, сохранённые из универсального пульта, загруженные из приложения) | `/ext/infrared/` |
| `IR library file` | Библиотеки универсальных пультов | `/ext/infrared/assets/` |
| тестовый файл (`.irtest`) | Юнит-тесты декодеров/энкодеров | только в репозитории прошивки |

## Файл пульта

### Пример

```text
Filetype: IR signals file
Version: 1
#
name: Button_1
type: parsed
protocol: NECext
address: EE 87 00 00
command: 5D A0 00 00
#
name: Button_2
type: raw
frequency: 38000
duty_cycle: 0.330000
data: 504 3432 502 483 500 484 510 502 502 482 501 485 509 1452 504 1458 509 1452 504 481 501 474 509 3420 503
#
name: Button_3
type: parsed
protocol: SIRC
address: 01 00 00 00
command: 15 00 00 00
```

В файле может быть сколько угодно кнопок. Каждая начинается с `name:`; строка-комментарий `#` между кнопками
нужна только для читаемости.

### Поля

| Поле | Где | Тип | Описание |
|---|---|---|---|
| `name` | оба | строка | Имя кнопки. Только печатные ASCII-символы. Интерфейс Флиппера ограничивает имена 23 символами. |
| `type` | оба | строка | `parsed` или `raw`. |
| `protocol` | parsed | строка | Имя протокола точно как в [списке протоколов](/ru/infrared/protocols) (его выводит и CLI-команда `ir`). |
| `address` | parsed | hex | Адрес, всегда **4 байта**, младший байт первым: `EE 87 00 00` = `0x87EE`. |
| `command` | parsed | hex | Команда, всегда **4 байта**, младший байт первым. |
| `frequency` | raw | uint32 | Частота несущей в Гц, обычно `38000`. Допустимо 10000-1000000. |
| `duty_cycle` | raw | float | Коэффициент заполнения несущей, обычно `0.33`. Больше 0 и не больше 1. |
| `data` | raw | список uint32 | Тайминги в микросекундах между сменами уровня (импульс, пауза, импульс, …) через пробел. **Не больше 1024** значений. |

### Допустимые значения `protocol`

```text
NEC  NECext  NEC42  NEC42ext  Samsung32  RC6  RC5  RC5X  SIRC  SIRC15  SIRC20  Kaseikyo  RCA  Pioneer
```

::: tip Unleashed
`RCA` добавлен в Unleashed. `Pioneer` есть в прошивке, хотя официальный документ по формату его пока не упоминает.
:::

### Ручное редактирование

- Две строки заголовка (`Filetype`, `Version`) должны оставаться наверху.
- У каждой кнопки нужны `name` и `type`, затем либо `protocol`/`address`/`command`, либо `frequency`/`duty_cycle`/`data`.
- Чтобы объединить два пульта, скопируйте блоки кнопок одного файла в конец другого.
- Байты адреса/команды всегда должны быть 4 байта, даже если протокол использует меньше бит; лишние байты — `00`.
- Если Флиппер пишет *«Failed to load …»*, какое-то поле испорчено (например, строка `data` в RAW длиннее 1024
  значений или частота вне диапазона).

## Файлы библиотек

У файлов библиотек точно такая же структура, отличается только заголовок:

```text
Filetype: IR library file
Version: 1
# Last Updated 5th Oct, 2024
# Last Checked 5th Oct, 2024
#
# Model: Example TV 1234
name: Power
type: parsed
protocol: NEC
address: 07 00 00 00
command: 02 00 00 00
```

Универсальный пульт ищет сигналы **по имени**, поэтому имена должны точно совпадать с кнопками библиотеки (см.
таблицу на странице [Как прислать свои записи](/ru/infrared/captures#имена-кнопок-для-каждой-библиотеки)). Новые
модели дописываются в конец с комментарием `# Model: …` перед ними.

Файл библиотеки нельзя открыть через `Saved Remotes`: приложение ответит *«Library file … can't be opened as a remote»*.

## Тестовые файлы (`.irtest`)

Используются только юнит-тестами прошивки (`applications/debug/unit_tests/resources/unit_tests/infrared` в
репозитории). Похожи на файлы пультов, плюс тип `parsed_array` для целых последовательностей расшифрованных сообщений:

| Поле | Где | Тип | Описание |
|---|---|---|---|
| `name` | оба | строка | Имя сигнала, см. правила ниже. |
| `type` | оба | строка | `parsed_array` или `raw`. |
| `count` | parsed_array | uint32 | Число сообщений в массиве, минимум 1. |
| `protocol`, `address`, `command` | parsed_array | | Как выше, по одному на сообщение. |
| `repeat` | parsed_array | bool | Является ли сообщение повтором (кнопка удерживается). |
| `frequency`, `duty_cycle`, `data` | raw | | Как выше. |

Имена строятся как `<имя><номер_теста>`: `decoder_input1` (RAW-вход декодера, он же ожидаемый выход энкодера),
`decoder_expected1` (ожидаемый выход декодера, он же вход энкодера), `encoder_decoder_input1` (parsed-массив,
который должен пережить цикл «закодировать → декодировать»). Для каждого протокола такой тестовый файл обязателен.
