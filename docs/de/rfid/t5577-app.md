# T5577-App

Die App **T5577** (von @mishamyte, Teil von Unleashed) arbeitet mit einem T5577-/ATA5577-Rohling auf
**Blockebene** — mit dem Silizium, nicht mit der Karte, die er vorgibt zu sein. Sie kann die Blöcke des Chips lesen
und speichern, jeden Block bearbeiten oder sein Konfigurationswort zusammenstellen, einen gespeicherten Dump
zurückschreiben, testen, welche Blöcke Schreibvorgänge annehmen, das Tag wipen, sein Passwort löschen und ein
Passwort aus der Luft mitlesen, indem sie einem Lesegerät oder Cloner beim Beschreiben eines Tags zuhört.

Öffne sie über `Main Menu → Apps → RFID → T5577` (installiert als `/ext/apps/RFID/t5577.fap`). Die 125 kHz RFID-App
startet sie außerdem, wenn du unter **Saved** eine `.t5577`-Datei öffnest.

::: tip Unleashed
Diese App gibt es in der Stock-Firmware nicht. Clear Password und der T5577-Wipe lagen früher in den
**Extra Actions** der 125 kHz RFID-App; jetzt wohnen sie hier.
:::

## Hintergrund: was in einem T5577 steckt

| Page / Block | Inhalt |
|---|---|
| Page 0, Block 0 | **Konfiguration**: Modulation, Bitrate, Anzahl der gesendeten Datenblöcke (Max Block), Passwort-Bit und weitere Flags |
| Page 0, Blöcke 1–6 | Daten — der Frame der emulierten Karte |
| Page 0, Block 7 | Passwortspeicher (oder ganz normale Daten, wenn kein Passwort aktiv ist) |
| Page 1, Block 0 | Kopie der Konfiguration |
| Page 1, Blöcke 1–3 | Rückverfolgungsdaten aus der Fertigung (Blöcke 1–2 sind bei echten Chips gesperrt) |

## Hauptmenü

| Eintrag | Funktion |
|---|---|
| **Read Tag** | Alle Blöcke in einen Dump lesen |
| **Test Tag** | Herausfinden, welche Blöcke Schreibvorgänge annehmen (erst Backup, dann zurückschreiben) |
| **Saved** | Einen gespeicherten `.t5577`-Dump öffnen |
| **Wipe Tag** | Den Chip in den Leerzustand zurücksetzen |
| **Clear Password** | Ein Passwort entfernen: erst dein Wort, dann das Wörterbuch |
| **Sniff Password** | Einem Lesegerät / Cloner zuhören und die gesendeten Kommandos dekodieren |
| **Passwords** | Die Wörterbücher ansehen und eigene Wörter verwalten |

## Read Tag

1. `T5577 → Read Tag`. Lege das Tag auf die Rückseite des Flippers und halte still (*Finding tag*, dann
   `P0 block N…`).
2. Der Ergebnisbildschirm **T5577 read** zeigt `Block 0: XXXXXXXX` und eine Zusammenfassung wie
   `RF/64, password set, inverted`. Tasten: **Save**, **Info**, **Retry**.
   - **Info** zeigt die dekodierte Konfiguration (Modulation, Bit rate, Max block, die Flags PWD/AOR/ST/XM/POR,
     Password) und alle Blöcke von Page 0 und Page 1; nicht gelesene Blöcke erscheinen als Striche.
   - **Save** fragt *Name the dump* und speichert `/ext/lfrfid/<name>.t5577`.
3. **Read in part** heißt, dass das Tag mitten im Vorgang nicht mehr geantwortet hat — der Block, bei dem es
   verstummte, wird genannt. Halte es besser und versuche es erneut.
4. **Nothing found** — *Hold the tag still, or it needs a password*. Tasten **No pass** (erneut ohne Passwort) und
   **Password**.

::: danger Passwort-Lesevorgänge können ein offenes Tag beschädigen
Wählst du **Password**, erscheint *Only if it is protected — A password read writes block 0 of a tag that has no
password set*. Der Frame für einen Passwort-Lesevorgang ist genauso lang wie ein Schreibvorgang: An ein Tag
**ohne** Passwort gesendet schreibt er dein „Passwort" in Block 0, und das Tag wird als gar nichts mehr gelesen. Ein
schlecht gehaltenes Tag sieht genauso aus wie ein geschütztes — versuche es deshalb immer erst ohne Passwort. Stellt
die App später fest, dass das Tag kein Passwort wollte, warnt sie: *Tag wants no password — That frame wrote block 0.
Check it below, and wipe the tag if it reads wrong*.
:::

## Gespeicherte Dumps

`T5577 → Saved` listet `.t5577`-Dateien. Ein Dump öffnet ein Menü:

| Eintrag | Aktion |
|---|---|
| **Info** | Dekodierte Konfiguration und alle Blöcke |
| **Write to Tag** | Den Dump zurückschreiben (fragt *Write to tag* mit der Anzahl der Blöcke) |
| **Edit** | Blöcke bearbeiten |
| **Rename** / **Delete** | Die Datei verwalten (ein Dump kann das Passwort des Tags enthalten — lösche ihn, wenn es nicht auf der Karte bleiben soll) |

### Write to Tag

Schreibt nur die Blöcke, die der Dump wirklich gelesen hat, in der Reihenfolge des Proxmark3: Page 0 Blöcke 1–7,
Page 1 Blöcke 1–3, **Block 0 zuletzt**. Ein Block 0 voller Nullen wird nie geschrieben. Jeder Block wird danach
zurückgelesen. Mögliche Ergebnisse sind **Written!**, **Not written**, *Lost the tag at P0 block N*, *P0 block N
differs*, *Tag wants a password this dump has not* oder *P1 trace unchanged* (echte Chips verweigern Änderungen an
ihren Rückverfolgungsblöcken — das ist zu erwarten).

Beschreibt Block 0 eine Konfiguration, die der Flipper nicht dekodieren kann, wirst du vor dem Schreiben gewarnt, dass
*Nothing will read back*.

### Edit

**Edit blocks** listet jeden Block mit seinem Wert. Wähle einen Block, um ein neues 32-Bit-Wort einzutippen.
**Block 0** öffnet einen Konfigurationseditor mit benannten Feldern:

- **Modulation**: Direct, PSK1, PSK2, PSK3, FSK1, FSK2, FSK1a, FSK2a, ASK/MC, Biphase, Diphase
- **Bit rate**: RF/8, RF/16, RF/32, RF/40, RF/50, RF/64, RF/100, RF/128
- **Data blocks** (Max Block), **Password bit** (On/Off) und **Word** — das rohe Hex.

Beim Verlassen fragt *Save changes — Write the edited blocks back to the file*, ob gespeichert werden soll. Lehnst du
ab, wird die Änderung auch aus dem Speicher verworfen und kann nicht versehentlich auf ein Tag gelangen.

## Test Tag

Findet heraus, welche der Blöcke 1–7 von Page 0 tatsächlich einen Schreibvorgang annehmen. Fragt vorher
*Do not move the tag — A backup is saved, then every block is written and put back*.

- Der vollständige Dump wird vor jedem Schreibvorgang gelesen und als
  `/ext/lfrfid/t5577/T5577_before_test.t5577` gespeichert.
- In jedem Block wird ein Bit gekippt, der Block zurückgelesen und das Original wieder geschrieben und verifiziert.
- Ergebnisse: **Full T5577** (alles beschreibbar), **Nothing writeable**, *Stopped at block N*, *Lost tag at block N —
  Check it, then retry*, *Block N is not back* (stelle ihn aus dem Backup wieder her), **Tag has a password — Not
  supported yet**.
- Hat ein früherer Test ein Tag verändert zurückgelassen, warnt die App mit *Unfinished test*, bevor sie das Backup
  überschreibt.

## Wipe Tag

Bestätige *Wipe T5577 — Erases all data. The tag stops working as a key. Hold still while running* → **Wipe**. Die
Datenblöcke werden genullt und eine Standardkonfiguration geschrieben, dann wird das Ergebnis durch Zurücklesen
verifiziert.

- **Wiped!** — fertig; schreibe aus der 125 kHz RFID-App einen neuen Schlüssel.
- **Not wiped** — *No answer. Protected? Try Clear Password*, *The tag answered, but not as wiped* oder *Could not
  check what the tag holds*.

Der Wipe entfernt **kein** Passwort.

## Clear Password

1. `Clear Password` fragt *Password to try first* — gib das Passwort des Tags ein, wenn du es kennst (oder lass den
   Standard stehen).
2. Bestätige *Apply tag to Flipper's back and don't move it while it runs* → **Start**.
3. Die App prüft erst, ob das Tag überhaupt ungeschützt ist, probiert dann dein Passwort, dann dein
   **Benutzerwörterbuch** und dann das **Systemwörterbuch** (`Pass N of M`). Geschrieben wird nur Block 0, mit
   gelöschtem Passwort-Bit — genau der eine Schreibvorgang, den auch Proxmark3 nutzt.
4. Ergebnisse: **Cleared!** (*Opened by this password* — mit **Save**, um das Wort in deine Liste aufzunehmen), *The
   tag was asking for no password*, **Not cleared** (*No password matched, or no tag answered*) oder Fehler bei
   Wörterbuch/SD-Karte.

Block 7 behält nach dem Löschen den alten Passwortwert — entfernt wird nur das Schutz-Bit.

## Sniff Password

Holt ein Passwort durchs **Zuhören**, während ein Lesegerät oder Cloner mit einem Tag spricht. Der Flipper sendet
nichts und speist kein Feld — du kannst ihn also gefahrlos auf Hardware richten, die dir nicht gehört.

1. `Sniff Password`. Der Bildschirm zeigt *Listening* / *Hold on the cloner* und eine laufende Mitschrift.
2. Lege die Rückseite des Flippers dort auf den Cloner oder das Lesegerät, wo das Tag hingehört, und lass das Gerät
   seinen Schreib-/Lesevorgang machen.
3. Die Aufnahme endet nach einem vollständigen Kommando und anschließender Stille; der Ergebnisbildschirm zeigt, was
   zu hören war:
   - **Password** — *The cloner sent it* (ein passwortgeschützter Lese-/Schreibvorgang war zu hören);
   - **New password** — *Written to block 7* (der Cloner hat ein Passwort gesetzt);
   - **Maybe a password** — der 38-Bit-Frame könnte ein Passwort-Lesevorgang oder ein Schreibvorgang sein; beide
     Lesarten stehen unter **More**;
   - **No password** / **Commands heard** — *None of them carried a password*;
   - **Too much noise**, **Can't decode**, **Nothing heard**.
4. **More** listet jedes dekodierte Kommando (Reset, Read/Write mit oder ohne Passwort, mit Block und Daten).
   **Save** legt ein gefundenes Passwort in deinem Benutzerwörterbuch ab (bei einer aus Nachbar-Frames abgeleiteten
   Lesart fragt es zuerst *Save a deduction?*).

## Passwords

`T5577 Passwords` zeigt **System dict: N** und **User dict: N** mit **Add** und **List** (ein ausgewähltes Wort wird
gelöscht).

| Datei | Inhalt |
|---|---|
| `/ext/lfrfid/assets/t5577_dict.lfrfid` | Systemliste (Proxmark3-Passwörter, wird bei Firmware-Updates überschrieben) |
| `/ext/lfrfid/assets/t5577_dict_user.lfrfid` | Deine Wörter — von Clear Password zuerst probiert, bleiben über Updates hinweg erhalten |
