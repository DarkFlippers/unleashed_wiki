# Внесок і переклад

Ця вікі — сайт на [VitePress](https://vitepress.dev). Сторінки — звичайний Markdown, кожна сторінка існує
**в усіх мовах**, і кожна сторінка, що використовує джерело, **зазначає** його. Тут описано, як додати або
відредагувати сторінку, як працюють подяки і як додати цілу нову мову.

## Як організована вікі

Вміст лежить у `docs/` і розділений спочатку за мовою, а потім за розділом:

```
docs/              # English (the root locale)
  nfc/read.md
  community/credits.md
docs/ru/           # Russian — mirrors docs/ exactly
  nfc/read.md
  community/credits.md
```

Правило просте: **кожна сторінка існує за однаковим шляхом у всіх мовах.** Англійський `docs/nfc/read.md` і
російський `docs/ru/nfc/read.md` — це та сама сторінка двома мовами. Якщо сторінка є в одній мові, вона мусить
бути в усіх; запустіть `npm run check`, щоб побачити перелік відсутніх.

Розділи (теки верхнього рівня) зафіксовані у `docs/.vitepress/i18n/sections.ts`; у кожного розділу є `index.md`,
який працює як його головна сторінка.

## Frontmatter

Кожна сторінка починається з YAML-блоку frontmatter:

```yaml
---
title: Reading cards            # sidebar label + page title
order: 20                       # sort order inside the section sidebar (10, 20, 30…)
author: gromovyna               # ONLY if the page uses @gromovyna's material
original: [https://docs.flipper.net/zero/nfc/read, https://telegra.ph/...]
sources: [flipper-docs, unleashed-docs]
---
# Reading cards
```

- **`title`** — показується в боковому меню та як заголовок сторінки.
- **`order`** — позиція в боковому меню розділу. Використовуйте кратні 10, щоб пізніше можна було вставити
  сторінку між наявними. Сторінки `index.md` розділу є головними сторінками й `order` не отримують.
- **`author`** — ставте `gromovyna` (єдиний зареєстрований ключ автора) завжди, коли використано **будь-який**
  його матеріал, навіть частково. Це додає внизу виділену карточку подяки.
- **`original`** — перелік **точних** URL, з яких побудована сторінка. Обов'язковий завжди, коли використано
  джерело.
- **`sources`** — ключі всіх використаних джерел (див. нижче). Обов'язкові на кожній змістовій сторінці,
  включно зі сторінками-індексами розділів.

Зберігайте **однаковий frontmatter у всіх мовах** — переклад сторінки не змінює того, кому належить заслуга.

## Подяки обов'язкові

Якщо сторінка використовує *будь-яке* джерело — статтю, публікацію в каналі, документацію чи код прошивки — вона
мусить його зазначити. Блок подяк унизу кожної сторінки генерується з описаного вище frontmatter. Допустимі
ключі джерел визначені у `docs/.vitepress/sources.ts`; наразі це:

| Ключ | Джерело |
|---|---|
| `gromovyna` | статті та канал @gromovyna |
| `how2flipper` | канал @how2flipper_rus |
| `flipper-docs` | docs.flipper.net |
| `unleashed-docs` | документація Unleashed |
| `unleashed-readme` | ReadMe Unleashed |
| `unleashed-src` | початковий код прошивки Unleashed |
| `li0ard` | блог li0ard |

Побудова сторінки на основі коду прошивки також вважається використанням джерела: додайте `unleashed-src` до
`sources`, а відповідну теку з кодом на GitHub — до `original`.

Як формувати URL для `original`:

- **Документація Flipper** — `https://docs.flipper.net/zero/<path>` (тобто `zero_nfc_read.md` → `/zero/nfc/read`).
- **Документація Unleashed** — `https://github.com/DarkFlippers/unleashed-firmware/blob/dev/documentation/<File>.md`
  (пробіли як `%20`).
- **ReadMe** — `https://github.com/DarkFlippers/unleashed-firmware/blob/dev/ReadMe.md`.
- **gromovyna** — URL статті на `telegra.ph` та/або `https://t.me/gromovyna/<id>`.
- **how2flipper** — `https://t.me/how2flipper_rus/<id>`.

## Стиль викладу

- Справжня інструкція, а не копія. Переписуйте своїми словами, об'єднуйте джерела, що перетинаються,
  перебудовуйте структуру під читача.
- Орієнтуйтеся **насамперед на Unleashed**: коли Unleashed відрізняється від стокової прошивки, скажіть про це
  в блоці `::: tip Unleashed`.
- Кожна сторінка про функцію: що це → коли використовувати → нумеровані кроки з точними шляхами меню
  (`Main Menu → Sub-GHz → Read`), кнопки як `<kbd>OK</kbd>`, очікуваний результат, усунення проблем, пов'язані
  посилання.
- Технічні факти передавайте точно: частоти, формати файлів, шляхи на зразок `/ext/subghz/`, команди CLI, назви
  протоколів, номери версій. Не вигадуйте функції — якщо не впевнені, краще не згадуйте.
- Використовуйте контейнери VitePress: `::: tip`, `::: warning`, `::: danger`, `::: details`. Єдиний дозволений
  «сирий» HTML — це `<kbd>`; жодних компонентів Vue.
- Внутрішні посилання — абсолютні й без розширення: `/nfc/mfkey` англійською, `/ru/nfc/mfkey` російською.
  Посилайтеся лише на сторінки, які існують.

## Додавання сторінки

1. Створіть `docs/<section>/<page>.md` з frontmatter і вмістом.
2. Створіть дзеркало **в кожній** іншій мові за тим самим шляхом (наприклад, `docs/ru/<section>/<page>.md`).
3. Додайте її до переліку в `index.md` розділу.
4. Запустіть `npm run check`, щоб переконатися, що сторінка є в усіх мовах, а потім
   `npx vitepress build docs`, щоб виявити неробочі посилання (вони повідомляються як помилки збірки).

Бокове меню генерується автоматично з файлів і їхнього `order`, тому жодного переліку для бокового меню
редагувати не потрібно.

## Скриншоти екрана пристрою

Екрани Flipper у `/screens/…` **згенеровані, а не зняті**. `npm run screens` компілює власний код GUI прошивки
(канву, `gui/modules/*` і види застосунків) і рендерить кожен екран у
`docs/public/screens/<section>/<name>.png`. Результат піксель у піксель збігається зі скриншотом із qFlipper: той
самий кадр 128x64, ті самі два кольори, масштаб ×4. Рендерер лежить у `scripts/screens/` — його `README.md`
описує вимоги, звідки береться чекаут прошивки і як формат виводу виведений із коду qFlipper.

Щоб додати новий екран:

1. Напишіть блок `SCREEN(...)` у `scripts/screens/specs/<section>.c`. Будуйте вид точно так, як це робить сцена
   застосунку (`submenu_add_item`, `widget_add_*`, `popup_set_*`, власні сетери вида), із реалістичними
   тестовими даними.
2. Запустіть `npm run screens` (або `bash scripts/screens/build.sh --only <section>/` для одного розділу).
3. Додайте посилання на PNG зі сторінки: `![alt text](/screens/<section>/<name>.png)`. Шлях **однаковий у всіх
   мовах**; перекладається лише альтернативний текст.

Ставте кожен скриншот поряд із кроком або екраном, який він ілюструє, а не галереєю на початку сторінки, і
обмежтеся кількома на сторінку. У `docs/public/screens/manifest.json` перелічені всі згенеровані екрани з їхніми
назвами, шляхами меню та сценою прошивки, з якої взято тестовий стан.

## Додавання нової мови

Реєстр мов — це `docs/.vitepress/i18n/`. Щоб додати мову `xx`:

1. **Скопіюйте рядки.** Скопіюйте `docs/.vitepress/i18n/en.ts` у `docs/.vitepress/i18n/xx.ts` і перекладіть у
   ньому всі рядки. Встановіть `prefix: 'xx'` (це стане префіксом `/xx/` в URL).
2. **Зареєструйте мову.** У `docs/.vitepress/i18n/index.ts` імпортуйте свій файл і додайте його до масиву
   `LOCALES`.
3. **Створіть сторінки.** Створіть `docs/xx/` як дзеркало `docs/` — ті самі імена файлів і шляхи — і перекладіть
   кожну сторінку. Frontmatter залишайте ідентичним (ті самі `author`, `original`, `sources`).
4. **Перевірте.** Запустіть `npm run check`, щоб побачити перелік сторінок, яких немає в новій мові, заповніть
   прогалини, а потім зберіть сайт.

::: tip Для вмісту `.vitepress/` чіпати не треба
Усе описане вище, окрім *додавання мови*, — це чистий Markdown у `docs/`. Бокове меню, навігація та блок подяк
генеруються автоматично — не торкайтеся `docs/.vitepress/`, якщо ви не додаєте саме мову або ключ джерела.
:::
