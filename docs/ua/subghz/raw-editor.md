# Sub-GHz RAW Edit

**Sub-GHz RAW Edit** (від Lechnio) — невеликий редактор осцилограм для RAW-записів `.sub` просто на пристрої. Запис із [Read RAW](/ua/subghz/read-raw) зазвичай містить секунди шуму навколо короткої посилки, яка вам потрібна. У RAW Edit ви знаходите справжній сигнал, позначаєте його й зберігаєте лише цю частину, а ще можете склеювати кілька файлів, вирізати фрагменти й декодувати позначену ділянку декодерами Sub-GHz із прошивки.

::: tip Unleashed
RAW Edit постачається з Unleashed як системний застосунок, і застосунок Sub-GHz відкриває його напряму: `Sub-GHz → Read RAW` (або `Saved`) → відкрити RAW-файл → <kbd>→</kbd> `More` → `Edit`. Пункт `Edit` показується лише тоді, коли RAW Edit встановлено. Коли ви виходите з редактора, вас повертає до Sub-GHz.
:::

**Коли це знадобиться:** обрізати довгий RAW-запис перед тим, як поділитися ним чи надіслати його, розділити один запис на окремі кнопки, склеїти кілька записів або з'ясувати, який протокол ховається у RAW-файлі.

## Головне меню

`Main Menu → Apps → Sub-GHz → Sub-GHz RAW Edit`:

- `Select .sub file` — відкрити в редакторі файл із `/ext/subghz`
- `Merge .sub files` — склеїти кілька файлів в один
- `Config` — параметри завантаження й склеювання
- `About` — версія й посилання на проєкт

Крім RAW-файлів, застосунок може завантажити будь-який сигнал, який прошивка вміє кодувати (він перетворюється на RAW через внутрішній кодувальник). Для протоколів із кастомними кнопками спочатку пропонується вибір кнопки.

## Редактор

На екрані показано осцилограму зі смужкою загального огляду вгорі й два рядки нижче: `View:` (масштаб) і `Marked:` (довжина виділення A..B). Вибраний діапазон підсвічено пунктиром; маленькі позначки показують, що сигнал продовжується за краєм екрана.

| Кнопка | Дія |
|---|---|
| <kbd>←</kbd> / <kbd>→</kbd> | перемістити активний маркер (A або B); утримання прискорює рух |
| <kbd>↑</kbd> / <kbd>↓</kbd> | збільшити / зменшити масштаб |
| <kbd>OK</kbd> | перемкнути активний маркер між A і B |
| утримання <kbd>OK</kbd> | відкрити меню дій |
| <kbd>Back</kbd> | закрити редактор |

Меню дій (<kbd>↑</kbd> / <kbd>↓</kbd>, <kbd>OK</kbd> виконує, <kbd>Back</kbd> закриває) розташоване ліворуч, а поруч із ним — інформаційна панель лише для читання, яка показує кількість семплів у A..B, `TE` і визначене лінійне кодування (`PWM`, `PPM`, `Manchester`, `NRZ` або `1:1`):

- **Save** — записати в новий RAW-файл лише діапазон A..B. Ім'я пропонується як `<name>_edit1`, `_edit2`, … Збереження під наявним іменем запитує `Name exists, overwrite?`; сам відкритий файл ніколи не перезаписується.
- **Decode** — декодувати діапазон A..B декодерами Sub-GHz із прошивки (перебираючи всіх виробників для кожного пакета KeeLoq; пропускає BinRAW), згрупувати однакові пакети (`Decoded: N`) і зберегти вибраний як файл ключа, названий типово за протоколом і виробником (наприклад, `KeeLoq_Verex`). Кожний декодований запис також має кнопку **Locate**, яка прив'язує маркери A..B до його пакета (першого, якщо він повторюється). `No known protocol` означає, що нічого не декодувалося.
- **Cut** / **Copy** / **Paste** — натискайте <kbd>←</kbd> / <kbd>→</kbd> на пункті `Cut`, щоб перемикатися між **Cut** (вирізати A..B і помістити в буфер обміну; відхиляється, якщо після цього сигнал залишиться порожнім), **Copy** (скопіювати A..B у файл буфера обміну) і **Paste** (вставити вміст буфера на позицію активного маркера й виділити його).
- **Undo** — історія останніх **32** вирізань і вставок на SD-картці (не займає оперативної пам'яті). Коли правок більше однієї, відкривається список від найновіших із кількістю семплів та позиціями, і відкат повертає стан до вибраної правки. Перекреслено, коли скасовувати нічого.

## Обрізання запису — покроково

1. Запишіть пульт у [Read RAW](/ua/subghz/read-raw) і збережіть запис.
2. Відкрийте його в RAW Edit (через `More → Edit` або `Select .sub file`).
3. Зменште масштаб клавішею <kbd>↓</kbd>, щоб побачити, де саме посилки.
4. Перемістіть маркер **A** трохи перед посилкою клавішами <kbd>←</kbd>/<kbd>→</kbd>, натисніть <kbd>OK</kbd> і перемістіть маркер **B** трохи після неї.
5. Утримуйте <kbd>OK</kbd> → `Save`, прийміть або відредагуйте ім'я.
6. Перевірте збережений файл через `Sub-GHz → Saved`.

## Склеювання файлів

1. `Merge .sub files` → виберіть файл; у діалозі показується `Added N file(s)` і кількість семплів. Виберіть `Add more` або `Done`.
2. Усі файли мусять бути на одній частоті, інакше ви отримаєте `Frequency mismatch`.
3. Результат відкривається в редакторі як `merged`; збережіть його з меню дій.

## Config

| Пункт | Що робить |
|---|---|
| Normalize jitter | `OFF`/`ON` — прибирає джитер і дрейф тривалостей під час завантаження |
| Merge gap | тишина, яка вставляється між склеєними файлами, 0–1000 мс (типово 100); <kbd>OK</kbd> відкриває введення числа |
| Repeat | повторює кожний завантажений / склеєний сигнал 1–64 рази |

Рядок лише для читання внизу `Config` також показує, чи доступні в поточній збірці прошивки кастомні кнопки та збереження динамічного лічильника.

## Обмеження й усунення проблем

- **Без обмеження довжини (v2.0):** сигнали та склеєні записи зберігаються в робочому файлі на SD-картці, а в оперативній пам'яті тримається ковзне вікно запису (до ~38 000 семплів одразу після перезавантаження), залишаючи місце для Decode і Save. Коли маркер A або B виходить за край вікна, воно зсувається далі на чверть; зменшення масштабу зупиняється на межі вікна з повідомленням `No RAM to zoom out`.
- **Запит `Low RAM`** — показується, коли у вільну оперативну пам'ять вміщується менше ніж 15 000 семплів більшого сигналу; пропонує `Reboot` або `Continue`. `Decode` також перевіряє наявність ~8 КБ вільної пам'яті й повідомляє `Low memory` замість аварійного завершення.
- `Unsupported protocol or file is empty` — файл не є сигналом, який прошивка вміє кодувати.
- `Nothing in A..B` / `Range too small` — розведіть маркери далі один від одного.
- Довгі паузи зберігаються у файлі у своїй справжній тривалості.
