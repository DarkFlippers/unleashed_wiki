# Signal Settings

**Signal Settings** редагує вже збережений сигнал: його режим лічильника, поточний лічильник і код кнопки. Це
невеликий екран для досвідчених: він схований, поки не ввімкнено Debug, і майже все в ньому працює лише на тих
кількох протоколах, які підтримують [режими лічильника](/ua/subghz/counter-mode).

## Де він знаходиться {#where}

Це пункт у меню збереженого сигналу, а не пункт головного меню Sub-GHz. Відкрийте файл через `Sub-GHz → Saved`
(або з [Archive](/ua/apps/archive)) — меню буде таким:

`Emulate` · `Rename` · `Delete` · `Signal Settings`

## Як його показати {#enable}

`Signal Settings` додається до цього меню лише тоді, коли ввімкнено **Debug**. З вимкненим Debug пункту немає.

- Швидкий шлях: утримуйте <kbd>↓</kbd> на робочому столі, а потім утримуйте <kbd>OK</kbd> на інформаційному
  екрані ([Робочий стіл → Інформаційний екран пристрою](/ua/start/desktop#info-screen)).
- Або `Settings → System → Debug` = `ON` ([Налаштування](/ua/start/settings)).

## Три пункти {#items}

![Signal Settings: Counter Mode, Edit Counter і Edit Button](/screens/subghz/signal_settings.png)

| Пункт | Що робить |
|---|---|
| `Counter Mode` | <kbd>←</kbd>/<kbd>→</kbd> вибирають `System` (режим 0) або `Mode 1` … до межі протоколу. Вибір одразу записується у файл `.sub` рядком `CounterMode:`, після чого файл перезавантажується; в етер нічого не йде |
| `Edit Counter` | <kbd>OK</kbd> відкриває шістнадцяткове введення поточного лічильника із заголовком `Enter <N>-bits counter in HEX`, де N — довжина лічильника протоколу: 4 шістнадцяткові цифри (2 байти) до 16 біт і 8 цифр (4 байти) понад те |
| `Edit Button` | <kbd>OK</kbd> відкриває шістнадцяткове введення коду кнопки із заголовком `Enter <N>-bits button in HEX` — завжди один байт, 2 шістнадцяткові цифри |

Поточне значення кожного пункту показано в його рядку, у шістнадцятковому вигляді. Що самі режими роблять
з лічильником і як задати режим, правлячи файл на комп’ютері, описано на сторінці
[Режими лічильника](/ua/subghz/counter-mode#modes-by-protocol).

::: warning Підтвердження правки лічильника або кнопки виходить в етер
`Edit Counter` і `Edit Button` записують файл через шлях передавання: прошивка запускає відправлення з новим
значенням і відразу його зупиняє, а файл перезаписується в момент зупинки. Радіо вмикається на мить, тому робіть
це подалі від приймача, який ви не хочете відчинити.

Лічильник зберігається точно таким, яким ви його ввели: для цього одного перезапису режим лічильника та крок
[Counter Incr.](/ua/subghz/settings) не застосовуються. Під час правки кнопки крок натомість виставляється в 0,
тож зміна кнопки не зсуває лічильник.

Якщо відправлення відхилено — частота, на якій ця прошивка не передає, — файл не записується зовсім.
:::

## Протоколи з режимами лічильника {#protocols}

`Counter Mode` розблокований для п’яти протоколів. `System` — це режим 0, звичайний:

| Протокол | Варіанти |
|---|---|
| Nice FloR-S | `System`, `Mode 1`–`Mode 2` |
| CAME Atomo | `System`, `Mode 1`–`Mode 3` |
| Alutech AT-4N | `System`, `Mode 1`–`Mode 2` |
| KeeLoq | `System`, `Mode 1`–`Mode 10` |
| `Phoenix_V2` (V2 Phoenix) | `System`, `Mode 1`–`Mode 2` |

Порівняння йде за рядком `Protocol:` у файлі. На решті протоколів пункт заблокований.

## Заблоковані пункти {#locked}

Заблокований пункт не можна відкрити чи змінити, після натискання він показує `Not available for this protocol !`

- `Counter Mode` — протокол файла не входить до п’ятірки вище.
- `Edit Counter` — у протоколу немає лічильника. Це залежить і від виробника: у KeeLoq пункт заблокований для
  `AN-Motors`, який має лише псевдолічильник, і для `Unknown`.
- `Edit Button` — у посилці протоколу немає коду кнопки.

`Edit Button` розблокований і на статичних протоколах, які мають код кнопки, — Princeton, Dooya, GangQi,
Hollarm, Nord ICE, Proteco і Roger, — і працює там точно так само, як на динамічному сигналі.
