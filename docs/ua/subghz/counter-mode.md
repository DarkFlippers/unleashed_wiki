# Режими лічильника (експериментально)

**Counter Mode** змінює те, як просувається динамічний лічильник, коли Flipper передає збережений сигнал із
динамічним кодом. Мета — клон вашого оригінального пульта, який **не конфліктує** з ним, щоб і Flipper, і
оригінал можна було використовувати з тим самим приймачем без розсинхронізації. (Передісторія:
[Динамічні коди](/ua/subghz/rolling-codes).)

::: tip Unleashed
Режими лічильника є лише в Unleashed. Підтримувані протоколи: **Nice FloR-S, CAME Atomo, Alutech AT-4N,
KeeLoq, V2 Phoenix**.
:::

::: danger Прочитайте перед використанням
Не експериментуйте з обладнанням, до якого ви не маєте доступу. Якщо ви не впевнені, який режим працює для вашої
системи, і **не можете заново прописати свій оригінальний пульт** у приймач — не користуйтеся цими режимами. Вони
можуть розсинхронізувати або заблокувати ваш пульт. Якщо ви можете перевірити це на власному приймачі, розкажіть
команді Unleashed, що працює (issues на GitHub / чати спільноти).
:::

## Як задати режим

### Варіант 1 — редагування файла `.sub`

1. Скопіюйте файл із `/ext/subghz/` на ПК (через qFlipper, мобільний застосунок або картридер).
2. Додайте в кінець рядок:
   ```text
   CounterMode: X
   ```
   де `X` — номер режиму. Зверніть увагу на пробіл після двокрапки.
3. Скопіюйте файл назад.

```text
Filetype: Flipper SubGhz Key File
Version: 1
Frequency: 433920000
Preset: FuriHalSubGhzPresetOok650Async
Protocol: Nice FloR-S
Bit: 52
Key: AA AA AA AA AA AA AA
CounterMode: 1
```

### Варіант 2 — Signal Settings на Flipper

Коли увімкнено **Debug**, у меню збереженого сигналу з'являється додатковий пункт:
`Sub-GHz → Saved → <файл> → Signal Settings`. Його рядок `Counter Mode` пропонує `System` (режим 0) і `Mode 1` …
до останнього режиму, який має протокол, і одразу записує ваш вибір у файл. На тому ж екрані можна змінити
лічильник і код кнопки: див. [Signal Settings](/ua/subghz/signal-settings).

## Режими за протоколами {#modes-by-protocol}

Режим 0 завжди типовий: поводиться як звичайний пульт, лічильник зростає на значення глобального параметра
[Counter Incr.](/ua/subghz/settings) (типово +1) і після `0xFFFF` обнуляється.

### Nice FloR-S

| Режим | Лічильник | Примітки |
|---|---|---|
| 0 | +множник | типовий |
| 1 | `0x0001 / 0xFFFE` | приймач **floxi2r** |
| 2 | `0x0000 / 0x0001` | приймач **ox2** |

### CAME Atomo

| Режим | Лічильник | Примітки |
|---|---|---|
| 0 | +множник | типовий |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` | працює із зовнішнім CAME **RE432**, можливо, й з іншими |
| 2 | `0x807B / 0x807C / 0x007B / 0x007C` | працює із зовнішнім CAME **RE432**, можливо, й з іншими |
| 3 | заморожений | лічильник не інкрементується |

### Alutech AT-4N

| Режим | Лічильник | Примітки |
|---|---|---|
| 0 | +множник | типовий |
| 1 | цикл із 3 натискань: `0x0000` (×4), `0x0001` (×4), потім `0xFFFE` (×4) + `0xFFFF` (×4) за одне натискання (~0,85 с) | приймач **MCSW-3.3M** (3-тє натискання ресинхронізує через межу переповнення) |
| 2 | набір ресинхронізації за одне натискання (~1,5 с): `0x0000`–`0x0003` (по ×2) + `0x0004`–`0x0005` (по ×3) | інші плати приймачів; лічильник у файлі не змінюється, тому кожне натискання надсилає той самий набір |

### KeeLoq

| Режим | Лічильник | Примітки |
|---|---|---|
| 0 | +множник | типовий |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` | може працювати з деякими системами |
| 2 | `+0x3333` на передавання (13107) | наприклад, DoorHan |
| 3 | `0x8006 / 0x8007 / 0x0006 / 0x0007` | наприклад, Hormann EcoStar |
| 4 | `0x807B / 0x807C / 0x007B / 0x007C` | наприклад, Nice Smilo |
| 5 | `0x0000 / 0xFFFF` | чергує 0 і 65535 |
| 6 | заморожений | лічильник не інкрементується |
| 7–10 | набори для примусової ресинхронізації | DoorHan, Phantom / Hiland, див. нижче |

#### Режими 7–10: набори для примусової ресинхронізації (DoorHan, Phantom / Hiland)

Ці режими не крокують лічильник: кожне натискання надсилає **фіксований набір** кодів. Приймач ресинхронізується
лише тоді, коли чує два передавання з **послідовними** лічильниками, тому набір будується з послідовних пар,
розставлених так, щоб кожний hop залишався у вікні ресинхронізації приймача, а пари разом покривали весь простір
лічильника. Це витягує приймач із будь-якого стану. Лічильник у вашому файлі не змінюється, тому кожне натискання
надсилає той самий набір, а файл залишається придатним до використання.

Кожний набір повторює, код за кодом, те, що для відповідної родини плат надсилає пульт-клон. Режими 7–9 — клон
DoorHan Smart, режим 10 — клон Phantom / Hiland. `X` — лічильник у вашому файлі.

| Режим | Для чого | Набір | Час на натискання |
|---|---|---|---|
| 7 | найстаріші плати DoorHan | 12 кодів: `X / X+1`, чотири пари, що йдуть уперед кроком 15998 (кнопка 0), потім `X-2 / X-1`; перша й остання пари несуть вашу кнопку | ~1,3 с |
| 8 | DHRE, більшість новіших плат, клони для розсувних воріт | 12 кодів: `X / X+1`, чотири пари з інтервалом `+0x3334`, потім повернення до вашого лічильника, де `X+1` надсилається з вашою кнопкою | ~1,3 с |
| 9 | плати роллет CV01, інші старі плати | 3 коди з вашою кнопкою: `X + 0x8000`, `X-1`, `X+1`, кожний надсилається двічі | ~0,65 с |
| 10 | Phantom / Hiland | 2 коди з вашою кнопкою: абсолютні `0xFFFE`, `0xFFFF`, кожний надсилається тричі | ~0,4 с |

::: warning Режим 7 змінився
Режим 8 — це рівно те, що робив `CounterMode: 7` у попередніх релізах. Якщо у вас є файл із `CounterMode: 7`,
який працював, змініть його на `CounterMode: 8`.
:::

Подробиці:

- У довгих наборах (7 і 8) кожний код виходить в ефір **один раз** (оригінальний клон надсилає кожний два-три
  рази) — увесь набір будується в пам'яті, і його потроєння вимагало б 20 КБ замість 8 КБ. Повторне надсилання
  набору це не замінює: приймач, який уже ресинхронізувався, читає другий прохід як новий обхід і знову приводить
  ворота в дію, тоді як повтор одного коду підряд ігнорується як дублікат.
- Режим 10 ігнорує лічильник у вашому файлі. Без обходу одне натискання ресинхронізує приймач, який тримає
  будь-яке з 32768 значень нижче за `0xFFFE`, — саме там і стоїть приймач, що «втік» уперед від вашого пульта.
  Якщо не вийшло, надішліть ще раз.
- **Утримання** кнопки Send повторює набір, поки ви її тримаєте; приймач, який ресинхронізувався на першому
  проході, читає це як ще одне натискання. Повторне натискання Send під час відправлення набору **перериває**
  його.

### V2 Phoenix (Phox)

| Режим | Лічильник | Примітки |
|---|---|---|
| 0 | +множник | типовий |
| 1 | `0x0000 / 0x0001 / 0xFFFE / 0xFFFF` («ofex like») | перевірено, працює |
| 2 | `0x0000 … 0x0004` | може працювати |

## Усунення проблем і поширені питання

- **Файл не працює після додавання `CounterMode`** — перевірте синтаксис `CounterMode: X` (пробіл після
  двокрапки) і те, що номер допустимий для цього протоколу.
- **Хибний номер режиму?** Використовується останній режим із переліку для цього протоколу.
- **Чи потрібно це в кожному файлі?** Ні. Без `CounterMode` застосовується режим 0.
- **Чи може це пошкодити пульт/приймач?** Воно може розсинхронізувати ваш пульт, залежно від приймача. Не
  користуйтеся цим, якщо не зможете заново спарувати оригінал.
- **Який режим вибрати?** Якщо ви не впевнені — жодний. Краще зробіть [новий пульт](/ua/subghz/add-manually).
