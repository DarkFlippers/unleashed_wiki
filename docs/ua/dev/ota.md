# Процес OTA-оновлення

Як Фліппер встановлює пакет оновлення: що відбувається на кожному етапі, що міститься в маніфесті оновлення, що
означають коди помилок `[XX-YY]` і як збирати власні пакети.

Про те, як це виглядає з боку користувача (встановлення Unleashed через qFlipper, Web Installer або з SD-карти),
читайте в статті [Оновлення](/ua/start/updating). Якщо оновлення зірвалося серйозно — див.
[Відновлення](/ua/start/recovery).

## Виконання коду з RAM

У прошивці є особливий режим завантаження: спеціально підготовлений образ системи завантажується в **RAM**, і
керування передається йому. Код, що виконується з RAM, має повний доступ на запис до всієї флеш-пам’яті, що
неможливо, доки основна прошивка працює з тієї самої флеш-пам’яті. Саме цей режим використовує OTA-оновлювач,
зокрема й для оновлення радіостека на другому ядрі MCU.

## Три етапи

### 1. Резервне копіювання внутрішнього сховища (`/int`)

`/int` — це розділ флеш-пам’яті Фліппера, який займає весь простір, не задіяний прошивкою. Нова прошивка може мати
інший розмір, тож її встановлення переформатувало б розділи й знищило дані. Тому перед усім іншим поточний вміст
`/int` зберігається у звичайний архів `.tar` на SD-карті.

### 2. Оновлення пристрою

Основна прошивка завантажує в RAM **оновлювач** — особливу збірку прошивки — і запускає його. Оновлювач працює з
системною флеш-пам’яттю так, як описано в маніфесті оновлення:

1. Якщо пакет містить образ **радіостека**, його версія порівнюється зі встановленою. Якщо вони різні, старий стек
   видаляється, а новий записується і встановлюється. Встановленням займається пропрієтарний **FUS** від ST, що
   працює на Core2, і воно передбачає кілька перезапусків.
2. **Option Bytes** (низькорівнева конфігурація MCU) перевіряються і за потреби виправляються.
3. Завантажується файл прошивки `.dfu`, його цілісність перевіряється за CRC32, після чого він записується у флеш
   і верифікується.

### 3. Відновлення внутрішнього сховища та оновлення ресурсів

Система перезапускається в нову прошивку, відновлює збережений вміст `/int` і — якщо пакет містить архів ресурсів —
розпаковує його на SD-карту.

## Маніфест оновлення

До кожного пакета додається маніфест (файл `.fuf`) у Flipper File Format — звичайний текстовий файл із пар
«ключ — значення».

### Обов’язкові поля (саме в такому порядку)

| Ключ | Значення |
|---|---|
| `Filetype` | Сталий рядок `Flipper firmware upgrade configuration` |
| `Version` | Версія маніфесту, зараз `2` |
| `Info` | Довільний опис пакета |
| `Target` | Апаратна ревізія, під яку зібрано пакет |
| `Loader` | Назва файлу завантажувача другого етапу, що виконується з RAM |
| `Loader CRC` | CRC32 файлу завантажувача у шістнадцятковому вигляді, **little-endian** |

### Необов’язкові поля

Вони можуть бути порожніми — тоді оновлювач пропускає відповідні операції.

| Ключ | Значення |
|---|---|
| `Radio` | Назва файлу образу радіостека (постачається ST) |
| `Radio address` | Адреса, за якою встановлювати радіостек (з release notes ST) |
| `Radio version` | Major, minor, sub-версія, гілка, реліз і тип стека, упаковані в 6 шістнадцяткових байтів |
| `Radio CRC` | CRC32 образу радіостека |
| `Resources` | Назва файлу архіву з ресурсами для SD-карти — `resources.ths`, tar-архів, стиснений heatshrink (див. [Формат tar + heatshrink](/ua/dev/tar-heatshrink)) |
| `OB reference`, `OB mask`, `OB write mask` | Еталонні значення для перевірки і виправлення option bytes |

## Коди помилок

Процес побудований так, щоб бути максимально відмовостійким: жодна ризикована операція не починається, доки не
перевірено всі пов’язані з нею дані, тому пристрій не залишається оновленим наполовину й не перетворюється на
«цеглину». Якщо
щось іде не так, оновлювач дає змогу повторити спробу і показує код помилки `[XX-YY]`, де `XX` — операція, що
зірвалася, а `YY` — прогрес або деталі, на яких вона зірвалася.

| Етап | XX | YY | Значення |
|---|--:|---|---|
| Завантаження маніфесту оновлення | **1** | **13** | Оновлювач повідомив про невідповідність апаратної версії |
| | | **20** | Не вдалося отримати шлях до збереженого маніфесту |
| | | **30** | Не вдалося завантажити маніфест |
| | | **40** | Непідтримувана версія пакета оновлення |
| | | **50** | Пакет призначений для іншої апаратної цілі |
| | | **60** | Немає файлу DFU |
| | | **80** | Немає файлу прошивки радіостека |
| Резервне копіювання конфігурації | **2** | **0-100** | Помилка читання/запису ФС |
| Перевірка прошивки радіостека | **3** | **0-99** | Помилка читання файлу прошивки радіостека |
| | | **100** | Не збігається CRC |
| Видалення прошивки радіостека | **4** | **0** | Помилка команди SHCI Delete |
| | | **80** | Помилка очікування статусу команди |
| Запис прошивки радіостека | **5** | **0-100** | Помилка читання/запису блоку |
| Встановлення прошивки радіостека | **6** | **10** | Помилка команди SHCI Install |
| | | **80** | Помилка очікування статусу команди |
| Core2 зайнятий | **7** | **10** | Не вдалося запустити C2 |
| | | **20** | Не вдалося перевести C2 у режим FUS |
| | | **30** | Помилка в операції FUS |
| | | **50** | Не вдалося перевести C2 у режим стека |
| Перевірка option bytes | **8** | **yy** | Код option byte |
| Перевірка файлу DFU | **9** | **0** | Помилка відкриття файлу DFU |
| | | **1-98** | Помилка читання файлу DFU |
| | | **99-100** | Файл DFU пошкоджений |
| Запис у флеш | **10** | **0-100** | Помилка читання/запису блоку |
| Перевірка флеш-пам’яті | **11** | **0-100** | Помилка читання/запису блоку |
| Відновлення конфігурації | **12** | **0-100** | Помилка читання/запису ФС |
| Оновлення ресурсів | **13-15** | **0-100** | Помилка читання/запису SD-карти |

::: tip Що робити при помилці
- **1-50 / 1-13** — пакет призначений для іншої апаратної цілі: завантажте правильний.
- **2, 12, 13-15** — проблема з SD-картою: перевірте або переформатуйте картку й скопіюйте пакет заново.
- **3-100, 9-99/100** — пошкоджені файли: завантажте пакет ще раз.
- Спершу просто повторіть спробу — оновлювач саме для цього й зроблений. Якщо Фліппер зовсім не завантажується,
  скористайтеся [Відновленням](/ua/start/recovery).
:::

## Збірка пакетів оновлення

Не забудьте передати `DEBUG=0` — див. [Збірка прошивки](/ua/dev/build).

**Повний пакет** — прошивка, радіостек і ресурси для SD-карти:

```sh
./fbt COMPACT=1 DEBUG=0 updater_package
```

**Мінімальний пакет** — лише прошивка:

```sh
./fbt COMPACT=1 DEBUG=0 updater_minpackage
```

Результат лежить у `dist/<target>-<cfg>/` у вигляді папки `f7-update-<suffix>` і файлу
`flipper-z-f7-update-<suffix>.tgz`.

### Вибір іншого радіостека

Типово пакети використовують стек **Bluetooth Light**. Якщо ваша прошивка підтримує інший стек, передайте його тип
і бінарник:

```sh
./fbt updater_package COMPACT=1 DEBUG=0 COPRO_OB_DATA=scripts/ob_custradio.data COPRO_STACK_BIN=stm32wb5x_BLE_Stack_full_fw.bin COPRO_STACK_TYPE=ble_full
```

`COPRO_OB_DATA` має вказувати на файл у `scripts/` з еталонними даними Option Byte для цього типу стека. Інколи
також доводиться підтверджувати дію через `COPRO_DISCLAIMER=...` у командному рядку.

### Часткові пакети

Для нетипового вмісту викликайте `scripts/update.py` напряму. Наприклад, пакет, який встановлює лише стек BLE FULL:

```shell
scripts/update.py generate \
  -t f7 -d r13.3_full -v "BLE FULL 13.3" \
  --stage dist/f7/flipper-z-f7-updater-*.bin \
  --radio lib/stm32wb_copro/firmware/stm32wb5x_BLE_Stack_full_fw.bin \
  --radiotype ble_full
```

Усі параметри перелічує `scripts/update.py generate --help`.

## Встановлення пакета з CLI

Скопіюйте папку з розпакованим пакетом на SD-карту й виконайте:

```
update install /ext/update/f7-update-local/update.fuf
```

У [CLI](/ua/dev/cli#update) також є команди `update backup` і `update restore` для внутрішнього сховища.
