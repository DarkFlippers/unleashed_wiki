# Апаратні таргети

Прошивка модульна: одна кодова база підтримує кілька апаратних конфігурацій. Усе, що відрізняється від плати до
плати — реалізація `furi_hal`, код ініціалізації плати, скрипти компонувальника, таблиці символів SDK, — зібрано
в **опис таргета**.

У репозиторії Unleashed у папці `targets/` є два таргети:

| Папка | Апаратна частина |
|---|---|
| `targets/f7` | Flipper Zero — типовий таргет (`TARGET_HW = 7`) |
| `targets/f18` | «Not Flipper Zero» — плата без радіочастотних частин; успадковує f7 |

Спільні заголовні файли лежать у `targets/furi_hal_include`.

## Як організований таргет

Кожен таргет живе у власній підпапці `targets/`. Він обов’язково містить `target.json` і може містити будь-які
інші файли, на які цей опис посилається. Типово `fbt` компілює **всі файли з початковим кодом** у папці таргета,
якщо вони не виключені явно. Таргети можуть **успадковувати** інший таргет, щоб не дублювати код.

## Поля `target.json`

| Поле | Тип | Значення |
|---|---|---|
| `include_paths` | список рядків | Папки (відносно таргета), що додаються до глобального шляху пошуку заголовних файлів C/C++ |
| `sdk_header_paths` | список рядків | Папки, заголовні файли з яких включаються до SDK |
| `startup_script` | ім’я файлу | Скрипт запуску, який виконує початкову ініціалізацію апаратної частини |
| `linker_script_flash` | ім’я файлу | Скрипт компонувальника для основного образу прошивки |
| `linker_script_ram` | ім’я файлу | Скрипт компонувальника для конфігурації «updater» (виконується з RAM) |
| `linker_script_app` | ім’я файлу | Скрипт компонувальника для файлів `.fap` |
| `sdk_symbols` | ім’я файлу | `.csv` з поточним описом SDK (API) для цього таргета |
| `linker_dependencies` | список | Бібліотеки, з якими компонується прошивка. Бібліотеки, яких тут немає, **не збираються**. Для кількох проходів компонування одне й те саме ім’я може знадобитися двічі |
| `inherit` | рядок | Таргет, з якого береться базова конфігурація. Значення-списки доповнюються, решта значень перевизначається |
| `excluded_sources` | список | Файли з успадкованих конфігурацій, які **не** потрібно збирати |
| `excluded_headers` | список | Заголовні файли з успадкованих конфігурацій, які **не** потрібно включати до SDK |
| `excluded_modules` | список | Імена бібліотек (модулів) `fbt`, які виключаються під час конфігурування збірки |

## Приклад: як f18 успадковує f7

Файл `targets/f18/target.json` (скорочено) показує успадкування та виключення на практиці — він бере все від f7 і
прибирає драйвери Sub-GHz, NFC, RFID, iButton та інфрачервоного порту:

```json
{
    "inherit": "7",
    "include_paths": [
        "furi_hal"
    ],
    "sdk_symbols": "api_symbols.csv",
    "excluded_sources": [
        "furi_hal_infrared.c",
        "furi_hal_nfc.c",
        "furi_hal_rfid.c",
        "furi_hal_subghz.c"
    ],
    "excluded_modules": [
        "nfc",
        "lfrfid",
        "subghz",
        "ibutton",
        "infrared"
    ]
}
```

## Застосунки та апаратна частина

Не кожен застосунок доступний на кожному таргеті.

- **Вбудовані застосунки:** сумісний набір застосунків вибирається параметром `FIRMWARE_APP_SET=...`
  (див. [fbt → набори застосунків прошивки](/ua/dev/fbt#firmware-app-sets)).
- **Зовнішні застосунки (FAP):** сумісні таргети перелічуються в `application.fam` застосунку. Наприклад, щоб
  збирати застосунок лише для f7, додайте:

```python
    targets=["f7"],
```

Для інших таргетів він збиратися не буде. Див. [Маніфести застосунків](/ua/dev/app-manifests).

## Збірка під конкретний таргет

Передайте `fbt` параметр `TARGET_HW` (і, за потреби, `FIRMWARE_APP_SET`). Наприклад, щоб зібрати прошивку для f18
і прошити її через USB:

```sh
./fbt TARGET_HW=18 flash_usb_full
```
