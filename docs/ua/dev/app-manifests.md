# Маніфести застосунків (.fam)

Кожен компонент прошивки — служби, користувацькі застосунки, сторінки налаштувань — розробляється незалежно й
описується файлом-маніфестом `application.fam`. Той оголошує базові властивості компонента і те, як він пов’язаний
з рештою системи.

Під час збірки `fbt` збирає всі маніфести, розв’язує їхні залежності й збирає **лише** ті компоненти, на які
посилається поточна конфігурація збірки (див. [fbt → набори застосунків прошивки](/ua/dev/fbt#firmware-app-sets)).

## Опис застосунку

Маніфест — це фрагмент коду Python, який викликає `App()` з іменованими аргументами. Обов’язкові лише
**`appid`** і **`apptype`**; решта необов’язкові, а деякі мають сенс тільки для певних типів застосунків.

### Типи застосунків (`apptype`)

`apptype` — це елемент перелічення `FlipperAppType`:

| Значення | Тип компонента |
|---|---|
| `SERVICE` | Системна служба, створюється на ранньому етапі запуску |
| `SYSTEM` | У меню не показується; запускається іншими застосунками або з CLI |
| `APP` | Звичайний застосунок у головному меню |
| `PLUGIN` | Збирається разом із прошивкою і потрапляє до меню Plugins |
| `DEBUG` | Видно лише в меню Debug, коли увімкнено режим налагодження |
| `ARCHIVE` | Єдиний і неповторний застосунок Archive |
| `SETTINGS` | Розміщується в системному меню Settings |
| `STARTUP` | Колбек, що виконується під час запуску системи; окремого застосунку не створює |
| `EXTERNAL` | Збирається як застосунок `.fap` |
| `METAPACKAGE` | Без коду; потрібен, щоб оголосити залежності та набори застосунків |

### Загальні параметри

| Параметр | Значення |
|---|---|
| `appid` | Рядковий ідентифікатор застосунку в системі збірки. Використовується в конфігураціях збірки та для розв’язання залежностей і конфліктів |
| `apptype` | Див. таблицю вище |
| `name` | Назва, яка показується в меню |
| `entry_point` | Функція C, що служить точкою входу. Імена C++ підлягають манглінгу — обгорніть функцію в `extern "C"` |
| `flags` | Внутрішні прапорці для системних застосунків. **Не використовуйте** |
| `cdefines` | Визначення препроцесора C, оголошені глобально для інших застосунків, коли цей застосунок є у збірці. Для зовнішніх застосунків — використовуються під час збірки самого застосунку |
| `requires` | Ідентифікатори застосунків, які додаються до збірки разом із цим застосунком |
| `conflicts` | Ідентифікатори застосунків, з якими цей конфліктує; якщо хоч один присутній, `fbt` перериває збірку |
| `provides` | Функціонально те саме, що `requires` |
| `stack_size` | Розмір стека в байтах, що виділяється під час запуску застосунку. Замалий → аварія через переповнення стека; завеликий → менше купи для застосунку |
| `icon` | Анімована піктограма з вбудованих ресурсів, використовується, коли застосунок вкомпілюваний у прошивку |
| `order` | Порядок сортування у своїй групі (менше = раніше). Використовується для хуків запуску та пунктів меню |
| `sdk_headers` | Заголовні файли C цього застосунку, які потрібно включити до API для зовнішніх застосунків |
| `targets` | Сумісні [апаратні цілі](/ua/dev/hardware-targets). Типово `["all"]` |
| `resources` | Папка в джерельному коді застосунку, яка пакується як ресурси для SD-карти (лише якщо застосунок є у збірці). Типово `""` — нічого |

::: tip
Під час вибору `stack_size` скористайтеся [командами CLI](/ua/dev/cli) `top` і `free`, щоб заміряти, скільки
пам’яті споживає ваш застосунок.
:::

### Параметри зовнішніх застосунків (FAP)

| Параметр | Значення |
|---|---|
| `sources` | Маски файлів для збирання джерельного коду в папці застосунку. Типово `["*.c*"]` (C і C++). Папка `lib` зарезервована для `fap_private_libs`. Маски, що починаються з `!`, виключають файли; маски без символів підстановки (`*`, `?`) вважаються точними шляхами. Приклад: `["*.c*", "!plugins"]` |
| `fap_version` | Рядок версії застосунку, типово `"0.1"`. Можна й кортеж `(x, y)`. Додаткові частини через точку дозволені, але в `.fap` зберігаються лише major і minor |
| `fap_icon` | Файл `.png`, 1-бітний колір, 10×10 px, вбудовується в `.fap` |
| `fap_libs` | Додаткові бібліотеки для компонування — дають доступ до функцій, яких не експортує прошивка, за ціною більшого `.fap` і більшої витрати RAM |
| `fap_category` | Підкатегорія застосунку; вона ж визначає папку в `apps/` на SD-карті |
| `fap_description` | Короткий опис (може бути порожнім) |
| `fap_author` | Автор (може бути порожнім) |
| `fap_weburl` | Домашня сторінка (може бути порожньою) |
| `fap_icon_assets` | Папка із зображеннями, які потрібно попередньо обробити й зібрати разом із застосунком |
| `fap_extbuild` | Частини джерельного коду, які збираються зовнішніми інструментами: список `ExtFile(path="file name", command="shell command")` |
| `fal_embedded` | Логічне значення, типово `False`. Лише для типу `PLUGIN`: вбудувати плагін у `.fap` застосунку-господаря як ресурс; під час запуску він розпаковується до `apps_assets/APPID` |
| `fap_private_libs` | Бібліотеки, що постачаються із застосунком у вигляді джерельного коду — див. нижче |

#### Команди зовнішньої збірки (`fap_extbuild`)

Команди виконуються з кореня прошивки. Проміжні файли мають потрапляти до тимчасової папки збірки застосунку.
`fbt` розгортає такі змінні (а також інші, внутрішні):

- `${FAP_WORK_DIR}` — тимчасова папка збірки застосунку
- `${FAP_SRC_DIR}` — папка з джерельним кодом застосунку

Приклад — збірка застосунку з джерельного коду на Rust:

```python
    sources=["target/thumbv7em-none-eabihf/release/libhello_rust.a"],
    fap_extbuild=(
        ExtFile(
            path="${FAP_WORK_DIR}/target/thumbv7em-none-eabihf/release/libhello_rust.a",
            command="cargo build --release --verbose --target thumbv7em-none-eabihf --target-dir ${FAP_WORK_DIR}/target --manifest-path ${FAP_SRC_DIR}/Cargo.toml",
        ),
    ),
```

#### Приватні бібліотеки (`fap_private_libs`)

Джерельний код бібліотек кладеться в підпапку `lib/` у папці застосунку. Кожна бібліотека — це виклик `Lib()`:

| Параметр `Lib()` | Значення | Типово |
|---|---|---|
| `name` | Назва папки бібліотеки (**обов’язковий**) | — |
| `fap_include_paths` | Шляхи (відносно бібліотеки), які додаються до шляхів включення застосунку | `["."]` |
| `sources` | Маски файлів джерельного коду бібліотеки, відносно її кореня | `["*.c*"]` |
| `cflags` | Додаткові прапорці компілятора | `[]` |
| `cdefines` | Додаткові визначення препроцесора | `[]` |
| `cincludes` | Додаткові шляхи включення, відносно кореня **застосунку** (наприклад, для заголовних файлів конфігурації) | `[]` |

Приклад:

```python
    fap_private_libs=[
            Lib(
                name="mbedtls",
                fap_include_paths=["include"],
                sources=[
                    "library/des.c",
                    "library/sha1.c",
                    "library/platform_util.c",
                ],
                cdefines=["MBEDTLS_ERROR_C"],
            ),
            Lib(
                name="loclass",
                cflags=["-Wno-error"],
            ),
        ],
```

Що з цим робить `fbt`:

- **mbedtls** — збирається з `lib/mbedtls`; `lib/mbedtls/include` додається до шляхів включення застосунку;
  компілюються лише три перелічені файли; для їхнього коду визначається `MBEDTLS_ERROR_C`.
- **loclass** — збирається з усього джерельного коду в `lib/loclass`; `lib/loclass` додається до шляхів включення;
  попередження **не** вважаються помилками (`-Wno-error`), що зручно для великого стороннього коду.

Обидві бібліотеки компонуються в застосунок.

## Повний файл `.fam`

Один файл може описувати кілька застосунків. Ось частина `applications/services/bt/application.fam`:

```python
App(
    appid="bt_start",
    apptype=FlipperAppType.STARTUP,
    entry_point="bt_on_system_start",
    order=70,
)

App(
    appid="bt_settings",
    name="Bluetooth",
    apptype=FlipperAppType.SETTINGS,
    entry_point="bt_settings_app",
    stack_size=1 * 1024,
    requires=[
        "bt",
        "gui",
    ],
    order=10,
)
```

Маніфест власного зовнішнього застосунку, який генерує `ufbt create APPID=test_app` (з
`scripts/ufbt/project_template/app_template/application.fam`):

```python
# For details & more options, see documentation/AppManifests.md in firmware repo

App(
    appid="test_app",  # Must be unique
    name="App test_app",  # Displayed in menus
    apptype=FlipperAppType.EXTERNAL,
    entry_point="test_app_app",
    stack_size=2 * 1024,
    fap_category="Examples",
    # Optional values
    # fap_version="0.1",
    fap_icon="test_app.png",  # 10x10 1-bit PNG
    # fap_description="A simple app",
    # fap_author="J. Doe",
    # fap_weburl="https://github.com/user/test_app",
    fap_icon_assets="images",  # Image assets to compile for this application
)
```

Більше прикладів можна знайти у файлах `.fam` по всій прошивці — наприклад,
`applications/system/*/application.fam` для додаткових застосунків Unleashed.
