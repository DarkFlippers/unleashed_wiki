# Flipper Build Tool (fbt)

`fbt` — єдина точка входу для збірки, прошивання, налагодження та перевірки стилю коду прошивки. Запускається як
`./fbt` (або `fbt.cmd` у Windows) з кореня репозиторію. Усередині це обгортка над системою збірки
[SCons](https://scons.org/).

Якщо потрібно лише збирати й налагоджувати **один застосунок**, повне дерево прошивки не знадобиться — скористайтеся
[uFBT](https://pypi.org/project/ufbt/) (див. [Перший застосунок на C](/ua/dev/first-app-c)).

## Оточення {#environment}

Єдине, що обов’язково має бути встановлене, — це `git`. Під час першого запуску `fbt` завантажує й розпаковує
готовий тулчейн і налаштовує змінні оточення **лише для себе** — ваш глобальний `PATH` не змінюється.

Щоб скористатися вбудованим тулчейном поза `fbt` (наприклад, вручну викликати `arm-none-eabi-gdb`), відкрийте
*оболонку fbt*:

- Windows: запустіть `scripts/toolchain/fbtenv.cmd`
- Linux / macOS: виконайте `source scripts/toolchain/fbtenv.sh` у новій оболонці
- або введіть `` . `./fbt -s env` `` у своїй оболонці (не забудьте початкову `.`)

Змінні оточення, що впливають на поведінку `fbt`:

| Змінна | Дія |
|---|---|
| `FBT_NOENV=1` | Пропустити завантаження й налаштування тулчейна; усі інструменти вже мають бути в `PATH` (у Windows недоступно) |
| `FBT_TOOLCHAIN_PATH=…` | Каталог, у який розпаковувати тулчейн (типово — `toolchain/` у корені репозиторію) |
| `FBT_VERBOSE=1` | Додатковий налагоджувальний вивід від `fbt` і скриптів тулчейна |
| `FBT_NO_SYNC=1` | Не виконувати `git submodule update --init` під час кожного запуску |

Як задати змінну для одного запуску:

```sh
# Linux / macOS
FBT_NO_SYNC=1 ./fbt ...
```

```bat
:: Windows (cmd)
set "FBT_NO_SYNC=1"
```

Решта змінних описана в джерельному коді скриптів `fbt` і `fbtenv`.

## Виклик fbt

Передайте параметри конфігурації та потрібні цілі:

```sh
./fbt COMPACT=1 DEBUG=0 VERBOSE=1 updater_package copro_dist
```

Щоб очистити вказані цілі (як `make clean`), додайте `-c`.

`fbt` відслідковує залежності, тож достатньо назвати найвищу потрібну ціль — усе, від чого вона залежить,
буде перезібрано автоматично.

## Каталоги збірки

Прошивка й оновлювач збираються в окремі підкаталоги `build/`, названі за налаштуваннями оптимізації (`COMPACT`,
`DEBUG`). Для IDE на останній зібраний варіант завжди вказує посилання `build/latest` — разом із
`compile_commands.json`, який потрібен для автодоповнення коду.

::: info
`build/latest` і база даних компіляції оновлюються лише **цілями збірки прошивки**. Прошивання чи збірка пакетів
оновлення для *іншої* конфігурації debug/release або іншої апаратної цілі не переносить `build/latest`.
:::

## Інтеграція з VS Code {#vs-code-integration}

```sh
./fbt vscode_dist
```

копіює готову конфігурацію оточення до `.vscode/`. Відкрийте корінь прошивки через **File → Open Folder**.

- Щоб використати інший мовний сервер замість типового `cpptools`, виконайте
  `./fbt vscode_dist LANG_SERVER=<language-server>`. Підтримуються `cpptools` (типово) і `clangd`.
- Під час першого запуску вам запропонують рекомендовані розширення (перелічені в `.vscode/extensions.json`) —
  встановіть їх.
- Задачі збірки викликаються через <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd>.
- Для налагодження потрібен підтримуваний зонд: Wi-Fi Devboard зі стоковою прошивкою (Blackmagic), ST-Link і
  сумісні або J-Link (лише у VS Code; інструменти J-Link не входять до комплекту —
  [завантажте](https://www.segger.com/downloads/jlink/) їх і додайте до `PATH`).
- Без зонда прошивку все одно можна встановлювати через USB.

## Основні цілі {#high-level-targets}

Саме ці цілі використовуються найчастіше.

| Ціль | Що робить |
|---|---|
| `fw_dist` | Збирає прошивку та публікує її в `dist/`. **Типова ціль**, якщо жодної не вказано |
| `fap_dist` | Збирає зовнішні застосунки (FAP) і публікує їх у `dist/` |
| `updater_package` | Повний пакет самооновлення: DFU прошивки + радіостек + ресурси для SD-карти |
| `updater_minpackage` | Мінімальний пакет оновлення: лише DFU прошивки |
| `copro_dist` | Збирає разом бінарники Core2 FUS і радіостека для qFlipper |
| `flash` | Прошиває через SWD підтримуваним зондом (визначається автоматично; перевизначається через `SWD_TRANSPORT=...`, а конкретний зонд із кількох вибирається через `SWD_TRANSPORT_SERIAL=...`) |
| `flash_usb`, `flash_usb_full` | Збирає, завантажує і встановлює пакет оновлення через USB (мінімальний / повний пакет) |
| `debug` | Збирає й прошиває прошивку, після чого підключає GDB із завантаженим `.elf` прошивки |
| `debug_other`, `debug_other_blackmagic` | Підключає GDB без завантаження жодного `.elf`; зовнішні файли `.elf` додаються командою `add-symbol-file` |
| `updater_debug` | Підключає GDB із завантаженим `.elf` оновлювача |
| `devboard_flash` | Оновлює Wi-Fi Devboard; додаткові аргументи — через `ARGS="..."`, наприклад `ARGS="-c dev"` |
| `blackmagic` | Налагоджує прошивку через зонд Blackmagic (Wi-Fi Devboard) |
| `openocd` | Просто запускає OpenOCD; додаткові аргументи — через `ARGS="..."` |
| `get_blackmagic` | Виводить адресу Blackmagic у форматі GDB remote (для інтеграції з IDE) |
| `get_stlink` | Виводить серійні номери підключених зондів ST-Link (для `SWD_TRANSPORT_SERIAL=...`) |
| `lint`, `format` | Перевіряє / переформатовує код C за допомогою clang-format (`.clang-format`); додаткові аргументи — через `ARGS="..."` |
| `lint_py`, `format_py` | Перевіряє / переформатовує Python, файли збірки та маніфести за допомогою [black](https://black.readthedocs.io/en/stable/index.html) |
| `lint_img`, `format_img` | Перевіряє / виправляє графічні ресурси (глибина кольору, видалення метаданих) |
| `lint_all`, `format_all` | Запускає всі лінтери / форматувальники |
| `firmware_pvs` | Звіт PVS-Studio (PVS-Studio має бути в `PATH`) |
| `doxygen` | Генерує документацію Doxygen; `doxy` ще й відкриває її в браузері |
| `cli` | Відкриває сесію [CLI](/ua/dev/cli) Фліппера через USB |

## Цілі прошивки

| Ціль | Що робить |
|---|---|
| `faps` | Збирає всі зовнішні застосунки та плагіни як `.fap` |
| `fap_<appid>` | Збирає один застосунок як `.fap` за його ідентифікатором, наприклад `fap_snake_game` |
| `fap_<appid>_list` | Генерує листинг джерельного коду й асемблера для `.fap` цього застосунку |
| `flash`, `firmware_flash` | Прошиває поточну збірку через SWD |
| `jflash` | Прошиває через JFlash за допомогою зонда J-Link (JFlash має бути в `PATH`) |
| `firmware_all`, `updater_all` | Збирає базовий набір бінарників |
| `firmware_list`, `updater_list` | Генерує листинги джерельного коду й асемблера |
| `firmware_cdb`, `updater_cdb` | Генерує `compilation_database.json` для IDE — працює без повної збірки |

Щоб примусово додати до зовнішньої збірки додаткові застосунки, скористайтеся `--extra-ext-apps` (див. нижче).

## Параметри командного рядка

| Параметр | Значення |
|---|---|
| `--options optionfile.py` | Завантажити файл зі значеннями конфігурації (типово `fbt_options.py`) |
| `--extra-int-apps=app1,app2,appN` | Примусово зібрати перелічені застосунки **у складі** прошивки (ціль `firmware`) |
| `--extra-ext-apps=app1,app2,appN` | Примусово зібрати перелічені застосунки як **зовнішні** (ціль `firmware_extapps`) |
| `--extra-define=A --extra-define=B=C` | Додаткові глобальні визначення C/C++; можна вказувати кілька разів |
| `--proxy-env=VAR1,VAR2` | Додаткові змінні оточення, які потрібно передати дочірнім процесам. Типово `fbt` очищає оточення; перелік завжди пропущених змінних лежить у `environ.scons` |

## Конфігурація

Типові значення лежать у `fbt_options.py`. Значення з командного рядка мають вищий пріоритет. Для **постійних
власних перевизначень** створіть поруч файл `fbt_options_local.py` — він обчислюється під час завантаження типових
параметрів, тож відслідковуваний у git файл правити не доведеться. Повний перелік параметрів виводить `./fbt -h`.

Помітні типові значення Unleashed із `fbt_options.py`:

| Параметр | Типово | Примітки |
|---|---|---|
| `FIRMWARE_ORIGIN` | `"Unleashed"` | Показується в інформації про пристрій |
| `TARGET_HW` | `7` | Flipper Zero (f7); див. [апаратні цілі](/ua/dev/hardware-targets) |
| `COMPACT` | `1` | Оптимізація за розміром |
| `DEBUG` | `1` | Для збірок, які встановлюються, передавайте `DEBUG=0` |
| `DIST_SUFFIX` | `"local"` | Суфікс у назвах вихідних файлів |
| `COPRO_STACK_TYPE` | `"ble_light"` | `ble_full` підтримується, але може не вміститися в налагоджувальні збірки |
| `FIRMWARE_APP_SET` | `"default"` | Див. нижче |

### Набори застосунків прошивки {#firmware-app-sets}

Те, які застосунки потрапляють у прошивку, визначає `FIRMWARE_APPS` — відображення *назва конфігурації → кортеж
ідентифікаторів застосунків*. Потрібний набір вибирається параметром `FIRMWARE_APP_SET`. Unleashed описує два
набори:

```python
FIRMWARE_APPS = {
    "default": [
        # Svc
        "basic_services",
        # Apps
        "main_apps",
        "system_apps",
        # Settings
        "settings_apps",
    ],
    "unit_tests": [
        "basic_services",
        "updater_app",
        "radio_device_cc1101_ext",
        "unit_tests",
        "infrared",
        "archive",
    ],
}
```

Наприклад, щоб зібрати образ із юніт-тестами:

```sh
./fbt COMPACT=1 DEBUG=0 FIRMWARE_APP_SET=unit_tests
```

Чому такій збірці потрібен `DEBUG=0`, описано на сторінці [Юніт-тести](/ua/dev/unit-tests).
