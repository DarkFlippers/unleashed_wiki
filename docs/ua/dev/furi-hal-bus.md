# FuriHalBus API

Якщо ваш застосунок звертається до периферії MCU напряму (таймери, ADC, DMA, …), він має вмикати й вимикати її
тактування через **FuriHalBus**. Помилка тут навмисно призводить до падіння Flipper, тому прочитайте цю сторінку
перед тим, як писати низькорівневий код.

## Основи

Під час запуску системи більшість периферійних блоків тримаються **в стані скидання й без тактування**. Це
економить енергію та гарантує, що перед використанням блок завжди перебуває у відомому стані. Частину критично
важливої периферії система вмикає відразу; решту має явно увімкнути той, хто нею користується.

> Тут *«система»* означає будь-який код, що належить операційній системі, драйверам апаратної частини або
> вбудованим застосункам.

| Виклик | Що робить | Передумова — інакше **падіння** |
|---|---|---|
| `furi_hal_bus_enable()` | Подає тактування на блок і виводить його зі скидання | Блок має бути **вимкнений** (увімкнути його двічі не можна) |
| `furi_hal_bus_disable()` | Повертає блок у стан скидання й знімає тактування | Блок має бути **увімкнений** |
| `furi_hal_bus_reset()` | Скидає всі його регістри до типових значень, не вимикаючи сам блок | Блок має бути **увімкнений** |

Типове використання:

```c
#include <furi_hal_bus.h>

furi_hal_bus_enable(FuriHalBusTIM1);
// ... configure and use TIM1 ...
furi_hal_bus_disable(FuriHalBusTIM1);
```

## Категорії периферії

Вбудована периферія ділиться на три групи:

1. та, яку система вмикає під час запуску й ніколи не вимикає;
2. та, яку система вмикає й вимикає на вимогу;
3. та, яку вмикає й вимикає код користувача.

### 1. Периферія, що завжди увімкнена

Її вмикає система. Код користувача **ніколи** не має її вимикати.

| Блок | Де вмикається |
|:-:|:-:|
| DMA1, DMA2, DMAMUX | `furi_hal_dma.c` |
| GPIOA, GPIOB, GPIOC, GPIOD, GPIOE, GPIOH | `furi_hal_resources.c` |
| PKA, AES2, HSEM, IPCC | `furi_hal_bt.c` |
| FLASH | вмикається апаратно |

### 2. Системна периферія на вимогу

Її вмикає й вимикає система. Не звертайтеся до неї напряму — користуйтеся відповідним API. Якщо ви все ж обходите
API, доведеться увімкнути блок самостійно й вимкнути його, коли робота завершена.

| Блок | Заголовний файл API |
|:-:|:-:|
| RNG | `furi_hal_random.h` |
| SPI1, SPI2 | `furi_hal_spi.h` |
| I2C1, I2C3 | `furi_hal_i2c.h` |
| USART1, LPUART1 | `furi_hal_serial.h` |
| USB | `furi_hal_usb.h` |

### 3. Спільна периферія на вимогу

Типово не увімкнена. Код користувача **мусить** вмикати її щоразу, коли нею користується. Частину цих блоків
система теж використовує для деяких функцій — тоді вона займає блок лише на час роботи цієї функції.

| Блок | Використовує система | Призначення |
|:-:|:-:|:--|
| CRC | | |
| TSC | | |
| ADC | | |
| QUADSPI | | |
| TIM1 | так | subghz, lfrfid, nfc, infrared тощо |
| TIM2 | так | subghz, infrared тощо |
| TIM16 | так | динамік |
| TIM17 | так | cc1101_ext |
| LPTIM1 | так | таймер режиму tickless idle |
| LPTIM2 | так | pwm |
| SAI1 | | |
| LCD | | |

::: warning
Якщо ваш застосунок використовує, скажімо, TIM2 у момент, коли активні Sub-GHz чи Infrared (або навпаки),
`furi_hal_bus_enable()` призведе до падіння, бо блок уже увімкнений. Переконайтеся, що конфліктна функція не
працює.
:::

## Канали DMA

`DMA1` і `DMA2` — особливий випадок: у кожного є кілька незалежних каналів, і частину з них використовує система.

| DMA | Канал | Використовує система | Призначення |
|:-:|:-:|:-:|:--|
| DMA1 | 1 | так | цифровий сигнал |
| DMA1 | 2 | так | цифровий сигнал |
| DMA1 | 3 | | |
| DMA1 | 4 | так | читач імпульсів |
| DMA1 | 5 | | |
| DMA1 | 6 | так | USART_Rx |
| DMA1 | 7 | так | LPUART_Rx |
| DMA2 | 1 | так | infrared, lfrfid, subghz |
| DMA2 | 2 | так | infrared, lfrfid, subghz |
| DMA2 | 3 | так | cc1101_ext |
| DMA2 | 4 | так | cc1101_ext |
| DMA2 | 5 | так | cc1101_ext |
| DMA2 | 6 | так | SPI |
| DMA2 | 7 | так | SPI |

Вільні для ваших потреб: **канали 3 і 5 DMA1**.
