# Формати файлів RFID 125 кГц

У `/ext/lfrfid/` лежать файли трьох видів:

| Розширення | Що описує | Чим створюється |
|---|---|---|
| `.rfid` | **Карту**: протокол + ID | Read → Save, Add Manually |
| `.t5577` | **Чип**: усі блоки T5577 | [Застосунок T5577](/ua/rfid/t5577-app) |
| `.ask.raw` / `.ask134.raw` / `.psk.raw` | Запис сирого сигналу | [RAW](/ua/rfid/raw) |

## `.rfid` — LF RFID-ключ

```text
Filetype: Flipper RFID key
Version: 1
Key type: EM4100
Data: 01 23 45 67 89
```

Файл зберігає один ключ того типу, який вказано в `Key type`.

| Поле | Опис |
|---|---|
| `Key type` | Назва протоколу, точно як у [таблиці протоколів](/ua/rfid/protocols) |
| `Data` | Дані ключа в hex; їхня довжина фіксована для кожного протоколу |

Дійсні значення `Key type` у цій прошивці: `EM4100`, `EM4100/32`, `EM4100/16`, `Electra`, `H10301`, `Idteck`,
`Indala26`, `Indala224`, `IoProxXSF`, `AWID`, `FDX-A`, `FDX-B`, `HIDProx`, `HIDExt`, `Pyramid`, `Viking`,
`Jablotron`, `Paradox`, `PAC/Stanley`, `Keri`, `Gallagher`, `Nexwatch`, `Radio Key`, `GProxII`, `Noralsy`.

Історія версій: 1 — початкова версія. Давні файли з `Key type: I40134` (3 байти) під час завантаження
перетворюються на `Indala26`.

::: tip
Ключ можна створити й на комп’ютері: напишіть чотири рядки, як вище, з правильним `Key type` і потрібною кількістю
байтів у `Data`, скопіюйте файл у `/ext/lfrfid/` — і він з’явиться в **Saved**.
:::

## `.t5577` — дамп T5577

```text
Filetype: Flipper T5577 dump
Version: 1
# Block 0: ASK/Manchester, RF/64, 2 data blocks, password enabled
Page 0 blocks read: 0 1 2 7
Page 0 Block 0: 00 14 80 50
Page 0 Block 1: 12 34 56 78
Page 0 Block 2: 9A BC DE F0
Page 0 Block 3: 00 00 00 00
Page 0 Block 4: 00 00 00 00
Page 0 Block 5: 00 00 00 00
Page 0 Block 6: 00 00 00 00
Page 0 Block 7: 0C 0D 0E 0F
Page 1 blocks read: 0 1
Page 1 Block 0: E0 15 00 1A
Page 1 Block 1: 20 24 10 00
Page 1 Block 2: 00 00 00 00
Page 1 Block 3: 00 00 00 00
Password: 0C 0D 0E 0F
```

Файл `.t5577` описує **кремній**, а файл `.rfid` — **карту**. T5577, налаштований як EM4100, можна зберегти і так, і
так, але ці формати не взаємозамінні: `.t5577` містить конфігурацію, яка визначає, як саме чип спілкується, і пароль,
що його захищає.

| Поле | Опис |
|---|---|
| `Page 0 blocks read` | Блоки сторінки 0, значення яких узято з чипа, через пробіл |
| `Page 0 Block 0..7` | Вміст блоку, 4 байти в hex, старшим байтом уперед. Блок 0 — конфігурація, блок 7 — сховище пароля |
| `Page 1 blocks read` | Блоки сторінки 1, які було прочитано |
| `Page 1 Block 0..3` | Блок 0 повторює конфігурацію; блоки 1–3 містять заводські дані відстеження |
| `Password` | Необов’язкове. Пароль, який **точно працює** на цьому чипі |

Головні правила:

- **Ключ є в кожного блоку**, прочитаного чи ні. Вмістом є лише блоки, названі в `blocks read`; решта — заповнювач, і
  його ніколи не можна записувати на мітку. Файл, у якому не вказано жодного блоку, відхиляється.
- Захищений чип не дає прочитати блок 0, потрібний для визначення типу, тому без пароля ви не отримаєте дампа взагалі
  (а не його частини). Частковий дамп означає, що мітка вийшла з поля.
- `Password` і `Page 0 Block 7` — це різні факти, і вони можуть не збігатися: блок 7 — це те, що в блоці було на
  момент читання (звичайне сховище, якщо пароль не ввімкнено), а `Password` — обліковий дані, які спрацювали.
  Скидання пароля лише очищає біт у блоці 0, тому блок 7 зберігає старе значення.
- Рядок коментаря з розшифруванням блоку 0 призначений лише для людей.

### Порядок відновлення

Коли дамп записується назад (застосунок T5577 → **Write to Tag**), порядок такий самий, як у Proxmark3:

1. Блоки 1–7 сторінки 0. Починаючи з блоку 7, запис мусить використовувати пароль, який уже зберігається в блоці 7.
2. Блоки 1–3 сторінки 1 (блок 0 сторінки 1 не записується ніколи). Справжні чипи не дають змінювати блоки 1–2 — це
   звітується як *unchanged*, а не як помилка.
3. Блок 0 сторінки 0 — **останнім**: він змінює те, як чип спілкується.
4. Записуються лише блоки, перелічені в `blocks read`.
5. Нульовий блок 0 **ніколи** не записується: чип із таким блоком взагалі нічого не відповідає, і дороги назад немає.

Кадри запису не отримують відповіді, тому про успіх можна дізнатися лише зворотним читанням блоків.

## `.raw` — RAW-записи

Двійкові файли, які створює RAW-читання. Вони починаються із заголовка:

| Поле | Тип | Значення |
|---|---|---|
| magic | uint32 | `0x4C464952` |
| version | uint32 | `1` |
| frequency | float | частота носійної, Гц (125000 або 134200) |
| duty_cycle | float | коефіцієнт заповнення носійної |
| max_buffer_size | uint32 | найбільший буфер у файлі |

Далі йдуть буфери, кожен із власним розміром на початку, що містять пари *(імпульс, тривалість)*, закодовані як
varint. Щоб їх розшифрувати, скористайтеся `rfid raw_analyze <filename>` у CLI.
