# MIFARE Classic

MIFARE Classic — найпоширеніша картка в системах контролю доступу, домофонах, готелях і старших транспортних
системах. Для Flipper вона ж і найцікавіша: шифр Crypto-1 зламано, тож, доклавши зусиль, можна відновити ключі
майже будь-якої картки, а потім емулювати її або записати на [заготовку](/ua/nfc/magic-cards).

## Будова пам'яті

| Тип | Сектори | Блоки | Ключів знайти | Типовий SAK |
|---|---|---|---|---|
| MIFARE Mini | 5 | 20 | 10 | `09` |
| MIFARE Classic 1K | 16 | 64 | 32 | `08` |
| MIFARE Classic 4K | 40 (32 × 4 блоки + 8 × 16 блоків) | 256 | 80 | `18` |

- **Блок** — це 16 байт. **Блок 0** (блок виробника) містить UID та дані виробника; на справжніх картках він
  доступний лише для читання — саме тому й існують заготовки.
- Останній блок кожного сектора — це **трейлер сектора**:
  `ключ A (6 байт) | біти доступу (4 байти) | ключ B (6 байт)`, наприклад
  `FF FF FF FF FF FF FF 07 80 69 FF FF FF FF FF FF` на чистій картці.
- Біти доступу визначають, який ключ може читати й записувати який блок. Часто ключ A читає, а ключ B записує;
  іноді ключ B сам доступний для читання — і тоді його не можна використовувати як ключ.

## Словники ключів

Flipper ніколи не «знає» ключів: він перебирає ключі-кандидати зі словників. Усі словники — це звичайні текстові
файли, по одному ключу з 12 шістнадцяткових цифр на рядок, `#` для коментарів
(див. [формат файлів](/ua/nfc/file-format)).

| Словник | Шлях | Хто його наповнює |
|---|---|---|
| **Системний** | `/ext/nfc/assets/mf_classic_dict.nfc` | Постачається з прошивкою (перезаписується під час оновлення). В Unleashed містить **понад 4000 ключів**. |
| **Користувацький** | `/ext/nfc/assets/mf_classic_dict_user.nfc` | Ви, MFKey, qUnleashed, *Save Keys to Dictionary*. Зберігається під час оновлень. |
| **CUID** (для однієї картки) | `/ext/nfc/assets/mf_classic_dict_<UID>.nfc` | MFKey / qUnleashed для карток зі *статичними шифрованими* nonce: великий список кандидатів для одного UID. |
| **Кеш ключів** | `/ext/nfc/.cache/<UID>.keys` | Записується автоматично, коли ви **зберігаєте** картку; використовується першим під час наступного зчитування того самого UID. |

::: tip Unleashed
Системний словник Unleashed містить великий набір додаткових ключів, зібраних спільнотою («Extra Mifare Classic keys
in system dict» у ReadMe). Екран завантаження CUID-словника з індикатором прогресу (*"CUID dictionary is loading"*)
з'явився у dev-збірці 1437 / релізі 094.
:::

### Керування користувацьким словником на пристрої

1. Відкрийте `Main Menu → NFC → Extra Actions → MIFARE Classic Keys`.

   ![Меню Extra Actions із пунктом MIFARE Classic Keys серед записів про словники](/screens/nfc/extra_actions.png)

2. На екрані показано **System dict: N** та **User dict: N**.
3. <kbd>OK</kbd> **Add**: введіть 6-байтовий ключ у шістнадцятковому вигляді та збережіть. Повторний ключ викличе
   попередження.
4. <kbd>→</kbd> **List** (лише якщо користувацький словник не порожній): виберіть ключ, щоб видалити його
   (*"Select key to delete:"*).

Файл `mf_classic_dict_user.nfc` можна редагувати й на комп'ютері (через qFlipper, qUnleashed або безпосередньо на
microSD-картці).

### Save Keys to Dictionary {#save-keys-to-dictionary}

Кожен збережений або щойно зчитаний дамп MIFARE Classic, у якому відомий хоча б один ключ, має в меню пункт
**Save Keys to Dictionary**. Він копіює всі ключі з цього дампа до користувацького словника, пропускаючи дублікати,
і повідомляє *"New keys: N, Already known: M"*. Найбільше це важливо для карток, ключі яких відновлено з
CUID-словника: інакше такі ключі живуть лише у файлі для цього UID та в самому дампі, тоді як
[NFC Magic](/ua/nfc/nfc-magic) заглядає тільки до кешу ключів і до користувацького й системного словників (саме це
@gromovyna називає «автоматичним збереженням ключів із перевіркою дублікатів» у своїй
[статті про qUnleashed](/ua/nfc/qunleashed)).

## Що відбувається під час зчитування MIFARE Classic

`Main Menu → NFC → Read`, тримайте картку нерухомо. Прошивка проходить такі етапи; заголовок екрана атаки показує,
який саме триває зараз.

1. **Кеш ключів.** Якщо ви вже зберігали цей UID, використовуються кешовані ключі й картка зчитується відразу.
2. **Словникова атака**, у такому порядку:
   - **MF Classic CUID Dictionary**: лише якщо існує файл для цього UID (перед нею — *"CUID dictionary is loading"*
     з індикатором прогресу; великий файл завантажується хвилинами).
   - **MF Classic User Dictionary**: якщо користувацький файл існує й не порожній.
   - **MF Classic System Dictionary**.

   На екрані видно `Keys found: X/Y`, `Sectors Read: X/Y`, номер поточного ключа та *"Unlocking sector: N"* /
   *"Reuse key check for sector: N"*.

   ![Атака системним словником: розблокування сектора 9, ключ 1244 з 2271, знайдено 19 із 32 ключів](/screens/nfc/dict_attack.png)

3. **Зчитування через бекдор.** Якщо чип має відомий **ключ-бекдор** (Fudan і деякі інші), у заголовку з'являється
   **Backdoor Read** / **(Backdoor)**, і сектори зчитуються без справжніх ключів. Паралельно збираються nonce.
4. **Nested-атаки** (щойно відомий хоча б один ключ): **PRNG Analysis**, **Nested Dictionary**, **Calibration**,
   **Nonce Collection** (*"Collecting from sector: N"*). Суфікс **(Hard)** означає, що картка має стійкий PRNG.
   Зібрані nonce дописуються до `/ext/nfc/.nested.log`.
5. Відкривається екран результату. Зелений світлодіод і звук успіху означають, що картку зчитано повністю, а
   короткий «напівуспіх» — що частини секторів усе ще немає.

Натисніть <kbd>OK</kbd> **Skip**, щоб перейти до наступного етапу (CUID → User → System → результат). <kbd>←</kbd>
запитує *"Exit to NFC Menu? All unsaved data will be lost"*. Якщо картку забрати, з'явиться **"Lost the tag! Make
sure the tag is positioned correctly."**; поверніть її на місце — і атака продовжиться.

Докладний розбір зі скриншотами кожної фази є на сторінці
[Nested-атаки та бекдори Fudan](/ua/nfc/nested-fudan).

### Після зчитування

Меню зчитаної картки MIFARE Classic (`More`) містить:

| Пункт | Коли | Що робить |
|---|---|---|
| **Save** | завжди | Зберігає дамп до `/ext/nfc/`. Також наповнює кеш ключів. |
| **Emulate** | завжди | Повна емуляція дампа. |
| **Extract MFC Keys** | картку зчитано не повністю | Запитує *"Save the Key?"* (Save/Skip), а потім збирає nonce зі зчитувача. Див. [MFKey32](/ua/nfc/mfkey). |
| **Unlock with Dictionary** | картку зчитано не повністю | Повторно запускає словникову та nested-атаку (наприклад, після того, як ви додали ключі). |
| **Crack nonces in MFKey32** | картку зчитано не повністю | Пропонує зберегти картку, а потім запускає [застосунок MFKey](/ua/nfc/mfkey-app) (**Run**). |
| **Show Keys** | завжди | *"Found MFC Keys"*: біти доступу, ключ A і ключ B по секторах та підсумки. |
| **Save Keys to Dictionary** | відомий хоча б один ключ | Див. вище. |
| **Info** | завжди | UID, ATQA, SAK, зведення щодо ключів і секторів; **More** показує шістнадцятковий дамп (`??` — невідомі байти). |

Для **збереженої** картки додатково доступні **Write to Initial Card**, **Update from Initial Card**,
**Restore to Original State** (якщо існує shadow-файл), **Rename** і **Delete**.

## Як добути ключі, яких не вистачає

Якщо зчитано не всі сектори, виберіть метод, який відповідає вашій ситуації:

| Ситуація | Метод |
|---|---|
| У вас є картка **і** доступ до зчитувача | [MFKey32](/ua/nfc/mfkey): Flipper емулює картку, а зчитувач видає свої ключі. |
| У вас є картка, відомий хоча б один ключ або чип має бекдор | Nested-атаки запускаються автоматично в `Read`; далі обчисліть ключі [застосунком MFKey](/ua/nfc/mfkey-app) або, значно швидше, через [qUnleashed](/ua/nfc/qunleashed). |
| Картка має **стійкий PRNG** | HardNested: обчислюється в qUnleashed або на комп'ютері, див. [Nested-атаки](/ua/nfc/nested-fudan). |
| Картки немає, є лише зчитувач | [MFKey32](/ua/nfc/mfkey) через `Extract MFC Keys` із головного меню NFC: ключі потраплять до користувацького словника на майбутнє. |
| Ключі диверсифіковані для кожної картки (наприклад, [Iron Logic](/ua/nfc/iron-logic)) | Кожна картка має власні ключі: відновлюйте їх для кожної картки окремо. |

Коли нові ключі додано, зчитайте картку знову (або відкрийте збережений файл → **Unlock with Dictionary**).

## Емуляція

1. `Main Menu → NFC → Saved → <картка> → Emulate`.
2. Піднесіть Flipper до зчитувача.

Сектори, які так і не було зчитано, емулюються як невідомі: зчитувач, якому вони потрібні, відхилить картку. Якщо
зчитувач записує щось на картку (баланс, лічильники, «динамічні» системи), зміни потрапляють до
[shadow-файлу](/ua/nfc/read#shadow-files).

::: warning Динамічні системи
Деякі системи перезаписують дані на картці під час кожного проходу (наприклад,
[Iron Logic у динамічному режимі](/ua/nfc/iron-logic-enrollment)). Емульована копія й оригінал тоді втрачають
синхронізацію, а користування обома може заблокувати оригінал.
:::

## Запис

- **Write to Initial Card** записує дамп назад **на ту саму картку** (UID має збігатися). Будь-яка інша картка дає
  *"Use source card! To write blanks use NFC Magic app"*. Якщо не всі блоки вдалося записати:
  *"Not all sectors were written correctly"*.
- Щоб клонувати картку на заготовку, скористайтеся застосунком [NFC Magic](/ua/nfc/nfc-magic) та відповідною
  [заготовкою](/ua/nfc/magic-cards). Вибирайте заготовку уважно: багато зчитувачів фільтрують картки Gen1.

## Якщо не працює

- **Ключі знайдено, але частину секторів так і не зчитано**: біти доступу можуть забороняти читання знайденим типом
  ключа; відновіть інший ключ (A або B).
- **Зчитування починається з довгого "CUID dictionary is loading"**: для цієї картки існує великий список
  кандидатів за її UID. Це очікувано після атаки на статичні шифровані nonce. Видаліть
  `/ext/nfc/assets/mf_classic_dict_<UID>.nfc`, коли картку буде повністю відновлено, а її ключі збережено до
  користувацького словника.
- **MFKey пише "Nonces already cracked" або не знаходить нічого нового**: після успішного відновлення очистьте
  `/ext/nfc/.nested.log` і `/ext/nfc/.mfkey32.log`; старі nonce все уповільнюють.
- **Відновлені ключі наче не використовуються**: перевірте, чи вони справді потрапили до
  `mf_classic_dict_user.nfc` (`Extra Actions → MIFARE Classic Keys → List`). Ключі, знайдені HardNested на
  комп'ютері, потрібно додавати вручну.
