# Застосунок MFKey (MFKey 4.1)

**MFKey** (автор — [@noproto](https://github.com/noproto)) відновлює ключі MIFARE Classic **безпосередньо на
Flipper** з nonce, зібраних застосунком NFC: nonce зі зчитувача (MFKey32) і nonce з картки, отримані nested-атаками.
Це інструмент для ситуацій, коли під рукою немає ні телефона, ні ПК; він повільніший за
[qUnleashed](/ua/nfc/qunleashed), зате працює будь-де — навіть у вас у кишені.

| | |
|---|---|
| Розташування | `Main Menu → Apps → NFC → MFKey` (`/ext/apps/NFC/mfkey.fap`) |
| Версія в Unleashed | **4.1** |
| Вхідні дані | `/ext/nfc/.mfkey32.log` (nonce зі зчитувача), `/ext/nfc/.nested.log` (nonce з картки) |
| Результат | `/ext/nfc/assets/mf_classic_dict_user.nfc` (ключі), `/ext/nfc/assets/mf_classic_dict_<UID>.nfc` (кандидати SEN) |

## Як користуватися

1. Спочатку зберіть nonce:
   - зі зчитувача: [MFKey32](/ua/nfc/mfkey) (`Extract MFC Keys`);
   - з картки: [nested-атаки](/ua/nfc/nested-fudan) під час `NFC → Read`.
2. Відкрийте `Main Menu → Apps → NFC → MFKey` або натисніть **Run** на екрані
   *"Now run Mfkey32 to extract keys"* у застосунку NFC (він з'являється після `Extract MFC Keys` і після
   `Crack nonces in MFKey32`).
3. На екрані буде **Ready**. Кнопка <kbd>→</kbd> **Help** показує
   *"Collect nonces by reading tag or reader in NFC app"*. Натисніть <kbd>OK</kbd> **Start**.
4. Спочатку MFKey перевіряє nonce за наявними словниками: **Dict solves: N (in progress)**, **Keys in dict: N**.
   Nonce, ключ до яких уже відомий, пропускаються.
5. Далі йде сама атака з трьома індикаторами: **Cracking: X/Y**, **Round: X/Y – ETA NN Sec** і
   **Total ETA NNN Sec**. Рядок **RAM** угорі показує вільну пам'ять у купі.
6. Після завершення ви почуєте сигнал і побачите **Complete**, **Keys added to user dict: N**, а для static
   encrypted nonce — ще й **SEN key candidates: N**.
7. Поверніться до застосунку NFC і зчитайте картку знову (або `Saved → <картка> → Unlock with Dictionary`).

Кнопка <kbd>←</kbd> перериває роботу й виходить (потік зупиняється коректно, а знайдені до того ключі все одно
записуються).

### Помилки

| Екран | Що означає |
|---|---|
| **No nonces found** | Немає ні `.mfkey32.log`, ні `.nested.log`. Спочатку зберіть nonce. Те саме показується для міток лише з HardNested: їхні nonce на Flipper зламати не вийде. |
| **Nonces already cracked** | Для кожного nonce у логах уже є ключ у ваших словниках. |
| **No free RAM** | Недостатньо пам'яті. Перезавантажте Flipper і спробуйте знову; закрийте інші застосунки. |

## Що змінилося в MFKey 4.x

Зі статті @gromovyna «MFKey 4.1 — швидше, вище, сильніше»: новий мажорний випуск вийшов досить тихо, але дав
великий приріст швидкості. Доступний у **dev-білдах Unleashed від 1251**. (На момент виходу статті зміни самого
застосунку були влиті й в офіційну прошивку, але потрібних змін на боці прошивки там не було.) Дякуємо @noproto
та команді.

Далі **SEN** = static encrypted nonce (див. [Nested-атаки](/ua/nfc/nested-fudan)).

**4.0**

- Підтримка нового формату словника SEN: відновлення ключів **у 10 разів швидше**.
- Старий формат словника SEN більше не підтримується.

**4.1**

- Відновлення ключів ще на **40 % швидше**; ефективніше використання пам'яті.
- Монолітний `mfkey.c` розбито на модулі: `mfkey_batch_prelude`, `mfkey_state_expansion`, `mfkey_bs_verify`,
  `mfkey_recovery`, `mfkey_dedup`.
- 32 кандидати перевіряються паралельно через SWAR (бітові операції замість поштучних перевірок).
- Попередньо обчислена «Super-LUT» на 2 КБ для раундів 0–3: одне індексоване завантаження на раунд замість обчислень.
- Порозрядне сортування O(n) замість швидкого сортування; дедуплікація через хешування Фібоначчі замість наївного
  перебору.
- Регістри FPU ядра M4 використовуються як додаткове місце для обчислень (`vmov`), що зменшує тиск на регістри.
- Цикл пошуку дублікатів розгорнуто у 8 разів за «методом Даффа».

### Швидкість на практиці

Автор перевіряв найважчий випадок: мітку зі **static encrypted nonce**. Для таких міток обчислені ключі не
перевіряються на льоту й не йдуть одразу до користувацького словника — замість цього будується словник
**кандидатів**, який потім треба перевірити на самій мітці. Тобто видобуваються **всі** ключі, які могли дати такий
nonce: найбільший словник, найдовший сценарій. За час тестів не було жодного *Out Of Memory*.

| Тест | Умови | Результат |
|---|---|---|
| Ключ Iron Logic | Мітка, зашифрована об'єктною картою [Iron Logic](/ua/nfc/iron-logic); ключа в словнику немає, атака через бекдор; **18 унікальних ключів на 32 сектори** | Повний цикл **6 год 8 хв**, понад **1.2 млн кандидатів**; потім ще кілька годин на перевірку кандидатів на мітці. |
| 1 сектор, 2 ключі | Та сама мітка (очищена), сектор 0 зашифровано випадковими різними ключами A і B | **17 хвилин**; перевірка кандидатів на одному секторі теж була швидкою. |

Для порівняння: перший тест на Proxmark3 з комп'ютером відновився за 24 секунди, тож тут Flipper ніколи не
зможе з цим конкурувати. Але якщо ви в дорозі або просто маєте час на фоновий розрахунок, Flipper у кишені
здатен відновити ключі й емулювати мітку. А оскільки диверсифікацію ключів люблять переважно системи на кшталт
Iron Logic, ймовірність натрапити на найдовший сценарій відносно невелика.

::: tip Unleashed
Unleashed містить MFKey 4.1 разом із потрібними для нього змінами на боці прошивки (словник CUID у `Read`, з
індикатором під час завантаження). Коли MFKey завершить роботу з SEN-міткою, скористайтеся
**Save Keys to Dictionary** на повністю зчитаному дампі, щоб скопіювати відновлені ключі до свого користувацького
словника — див. [MIFARE Classic](/ua/nfc/mifare-classic#save-keys-to-dictionary).
:::

## Поради

- Після успішного відновлення очищайте `/ext/nfc/.nested.log` і `/ext/nfc/.mfkey32.log`: старі nonce
  перевіряються заново під час кожного запуску.
- Якщо ви встановлювали застосунки окремо, переконайтеся, що старий `mfkey.fap` не перезаписав той, що йде з
  прошивкою.
- Значно швидші альтернативи: [qUnleashed](/ua/nfc/qunleashed) на телефоні чи ПК або проєкт
  [mfkey_desktop_cli](https://github.com/phntm-lab/mfkey_desktop_cli).
