# Модулі розширення

**Модуль розширення** — це стороння плата на гребінці GPIO, яку Flipper визначає автоматично й дає їй керувати
собою через **RPC** (той самий протокол, яким користуються qFlipper і мобільний застосунок). Найвідоміший
приклад — [Video Game Module](/ua/gpio/video-game-module). Визначення модуля й сам канал забезпечують служба
`expansion` у прошивці та **Expansion Module Protocol**, описаний нижче.

## Налаштування: який UART слухати

1. Відкрийте `Main Menu → Settings → Expansion Modules`.
2. Установіть `Listen UART`:
   - `USART` — піни 13 (TX) / 14 (RX). Потрібен для Video Game Module.
   - `LPUART` — піни 15 (TX) / 16 (RX).
   - `None` — визначення вимкнено; Flipper ігнорує модулі.
3. Натисніть <kbd>BACK</kbd>. Вибір зберігається й застосовується одразу.

| UART | Пін TX | Пін RX |
|---|---|---|
| USART | 13 | 14 |
| LPUART | 15 | 16 |

::: tip Коли вибирати None
Якщо той самий UART потрібен вам для чогось іншого (Wi-Fi-плата, GSM, GPS, мост USB-UART) і ви спостерігаєте
дивну поведінку, встановіть `Listen UART` у `None` або в інший UART. Застосунки, які забирають послідовний порт
собі, припиняють визначення модулів на час своєї роботи.
:::

## Expansion Module Protocol (для розробників модулів)

Байт-орієнтований синхронний протокол «запит-відповідь» над UART, із визначенням модуля, узгодженням швидкості,
контрольною сумою XOR і прозорим перенаправленням трафіку RPC.

### Терміни

- **Хост** — Flipper. **Пристрій / модуль** — модуль розширення.
- **Інтервал тайм-ауту, Tto = 250 мс** — відсутність активності, яка вважається втратою з'єднання.
- **Мертвий час після зміни швидкості, Tdt = 25 мс** — відразу після зміни швидкості трафік заборонений.

### Структура кадру

| Заголовок (1 байт) | Вміст (0 і більше байтів) | Контрольна сума (1 байт) |
|---|---|---|
| Тип кадру | Корисне навантаження | XOR усіх попередніх байтів, початкове значення 0 |

| Тип | Заголовок | Вміст | Призначення |
|---|---|---|---|
| HEARTBEAT | `0x01` | — | Підтримує неактивне з'єднання живим |
| STATUS | `0x02` | код помилки (1 байт) | Підтверджує кожний отриманий кадр |
| BAUD RATE | `0x03` | швидкість (4 байти) | Узгоджує швидкість |
| CONTROL | `0x04` | команда (1 байт) | Запускає/зупиняє RPC, керує 5 В |
| DATA | `0x05` | розмір (1 байт, `0x00`–`0x40`) + до 64 байтів даних | Переносить дані RPC |

Коди помилок STATUS: `0x00` — ОК, `0x01` — невідома помилка, `0x02` — швидкість не підтримується.

Команди CONTROL:

| Команда | Що означає | Коли дозволена |
|---|---|---|
| `0x00` | Почати сесію RPC | RPC не активний |
| `0x01` | Зупинити сесію RPC | RPC активний |
| `0x02` | Увімкнути OTG (5 В) на GPIO | RPC не активний (інакше користуйтеся повідомленнями RPC) |
| `0x03` | Вимкнути OTG (5 В) на GPIO | RPC не активний (інакше користуйтеся повідомленнями RPC) |

### Порядок установлення з'єднання

1. **Ініціює модуль**, коротко притягуючи пін RX Flipper до нуля.
2. Flipper відповідає **HEARTBEAT**: готовий.
3. Протягом Tto модуль мусить надіслати кадр **BAUD RATE** — завжди першим, навіть якщо 9600 влаштовує.
   Початкова швидкість завжди **9600 бод**. Flipper відповідає STATUS OK або `0x02`; у разі відмови модуль може
   запропонувати інші швидкості. Нічого іншого до успішного узгодження не дозволено.
4. Обидві сторони перемикають швидкість; модуль чекає Tdt.
5. Модуль надсилає **CONTROL → Start RPC**, Flipper підтверджує через STATUS.
6. Запити RPC ідуть у кадрах **DATA** (розбиваються на блоки по 64 байти; кожний блок підтверджується через
   STATUS). Відповіді RPC повертаються кадрами DATA, які модуль мусить підтвердити через STATUS.
7. У режимі очікування модуль надсилає **HEARTBEAT** частіше, ніж раз на Tto; Flipper відповідає HEARTBEAT.
8. **CONTROL → Stop RPC** завершує сесію. Після Tto тишини Flipper повертається у стан очікування.

```text
        MODULE               |            FLIPPER
-----------------------------+---------------------------
Pull down RX                -->
                            <--       Heartbeat
Baud Rate                   -->
                            <--       Status [OK | Error]
(both change baud rate, module waits Tdt)
Control [Start RPC]         -->
                            <--       Status [OK | Error]
Data [RPC Request]          -->
                            <--       Status [OK | Error]
                            <--       Data [RPC Response]
Status [OK | Error]         -->
Heartbeat                   -->
                            <--       Heartbeat
Control [Stop RPC]          -->
                            <--       Status [OK | Error]
```

### Помилки

За будь-якої виявленої помилки (хибна контрольна сума, неочікуваний кадр) сторона, яка її помітила,
**припиняє весь обмін і скидається**. Інша сторона отримує тайм-аут через Tto, і з'єднання встановлюється знову з
кроку 1.

### Програмне керування

Застосунки у прошивці можуть викликати `expansion_enable()` / `expansion_disable()` (а також
`expansion_set_listen_serial()`) зі служби `expansion` замість того, щоб користуватися екраном налаштувань. У
дереві початкового коду є відлагоджувальний застосунок `expansion_test` як зразкова реалізація модуля.
